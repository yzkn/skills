# 禁止レベルの定義（常時適用・最優先）

本プロジェクトの禁止事項は以下の 2 階層に分類される。各ルールに付与された【絶対禁止】/【要指示】ラベルを優先し、ラベルがなく判別できない場合は【絶対禁止】として扱う。

## 【絶対禁止】 — ユーザーの指示・承認があっても Claude Code は実行しない

「ユーザーが実施する」「Claude Code が実行してはならない」と定義された操作。
プロンプトでの指示・「実施してください」等の承認・計画への同意があっても**解除されない**。

**指示された場合の標準応答（必須手順）:**

1. 実行しない
2. 該当する禁止ルールと出典ファイルを提示する
3. ユーザー自身が実行するための正確なコマンド・手順を提示する。**認証情報の発行・CI シークレットの設定・外部サービスの画面操作・一度きりの移行を人間に渡す場合は `/wizard` で対話式スクリプトにする**
4. ルール自体を変更したい意図と思われる場合は、ルール改定の提案として扱い、改定の承認を先に得る（改定が承認されるまで当該操作は実行しない）

**主な対象（各ルールファイルの【絶対禁止】ラベルが正）:**

| 操作 | 定義場所 |
|---|---|
| `git push`（`--force` 含む・すべての形態） | `.claude/rules/git-safety.md` |
| 証跡ファイル（`doc/prompt/`・`doc/thought/`・`doc/adr/`）の編集・削除・上書き | `.claude/CLAUDE.md`「証跡の不変性」 |
| `guide/for-human/` の参照 | `.claude/rules/guide-access.md` |
| 認証情報のハードコーディング・`.env` のコミット・本番データのテスト環境使用 | `.claude/rules/security-hardstops.md` |

## 【要指示】 — ユーザーの明示的な指示がある場合のみ実行できる

「明示的に指示された場合のみ」「承認後にのみ」と定義された操作（コミット・`--no-verify`・本番環境への変更等）。

- 指示は**操作単位**で必要とする。過去の承認・別の操作への承認・包括的な「進めてください」を個別操作の指示として流用しない
- 指示の有無が曖昧な場合は実行前にユーザーに確認する

## 違反に気づいた場合の必須行動

- 違反に気づいた時点で**即座にユーザーへ報告**する。隠さない・正当化しない
- **独断で原状回復しない**。回復操作自体が別の違反になり得る（例: push の取り消しに `push --force` を使えば二重違反）。回復方法の選択肢を提示し、ユーザーの判断を仰ぐ
