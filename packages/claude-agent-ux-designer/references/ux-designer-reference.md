# ux-designer リファレンス — タスク種別ごとの詳細実施内容

ux-designer エージェントから参照されるリファレンス。エージェント定義本体は `.claude/agents/ux-designer.md`。
各タスク種別の作業を開始する前に、該当セクションを Read してから作業すること。

---

#### `research` — ユーザーリサーチ

以下の観点でリサーチを実施し、仮説・課題・インサイトを整理する。

| 観点 | 分析内容 |
|---|---|
| ユーザー層の定義 | ペルソナ・年齢層・技術習熟度・利用環境 |
| ジョブ・トゥ・ビー・ダン | ユーザーが達成しようとしている目標 |
| 現状の課題 | 既存 UI や業務フローの痛点・非効率な箇所 |
| 競合・参考事例 | 類似サービスのアプローチ（WebSearch で補足） |
| 優先度マトリクス | 課題を「影響度 × 発生頻度」で評価 |

成果物: `report/ux/YYYYMMDD_HHMMSS_research_<テーマ>.md`

---

#### `design` — UI/UX 設計

現在のフェーズ（基本設計 / 詳細設計）に応じた設計書を作成する。

**基本設計（`design/03_basic_design/`）**

| 項目 | 内容 |
|---|---|
| 情報アーキテクチャ | サイトマップ・ナビゲーション構造 |
| ユーザーフロー | 主要タスクの画面遷移図（Markdown テーブル形式） |
| ワイヤーフレーム概要 | 主要画面のレイアウト方針（テキスト・ASCII アート） |
| コンポーネント方針 | 共通 UI コンポーネントの一覧と利用場面 |

**詳細設計（`design/04_detailed_design/`）**

| 項目 | 内容 |
|---|---|
| 画面仕様書 | 各画面の要素・状態・バリデーション・エラー表示 |
| インタラクション仕様 | ホバー・クリック・フォーカス・アニメーションの挙動 |
| レスポンシブ方針 | ブレークポイント・モバイル対応の優先度 |
| データバインディング | 表示データ・入力値・APIとの対応関係 |

#### `prototype` — プロトタイプ作成

以下の3形式で成果物を生成する（プロンプトで指定がある場合は指定形式のみ）。

本タスクのスコープは構造・動線・インタラクションの検証にとどめる。ビジュアルデザイン（色・タイポグラフィ・シャドウ・アニメーション等）は `ui-designer` の `mockup` タスクが担う。

**① Markdown 仕様書** — `report/ux/YYYYMMDD_HHMMSS_prototype_<画面名>.md`

- 画面構成要素の一覧
- インタラクションフロー（Mermaid flowchart 形式）
- 状態遷移（初期状態・操作後状態・エラー状態）

**② ローフィデリティ HTML スケルトン** — `report/ux/YYYYMMDD_HHMMSS_prototype_<画面名>.html`

- セマンティック HTML5 で構造・動線を記述する
- スタイリングはレイアウト確認に必要なグレースケール最小限のみ（`background: #f5f5f5`・`border: 1px solid #ccc` 程度）
- カラー・タイポグラフィ・シャドウ等の視覚的仕上げは行わない（`ui-designer` に委ねる）
- JavaScript は最小限（状態切り替えなど必要最低限のみ）
- アクセシビリティ属性（`aria-*`・`role`・`alt`）を必ず付与

**③ Artifact レンダリング**

HTML スケルトンを Write で保存した後、Artifact ツールでブラウザプレビュー用に公開する。

#### `usability` — ユーザビリティテスト

テスト計画書または結果レポートを作成する。

**テスト計画書** (`report/ux/YYYYMMDD_HHMMSS_usability-plan_<対象>.md`)

| 項目 | 内容 |
|---|---|
| テスト目的 | 検証したい仮説・確認したい課題 |
| 対象ユーザー | 参加者プロフィール・人数 |
| タスクシナリオ | テスト参加者に実施してもらうタスクの一覧 |
| 評価指標 | タスク完了率・エラー数・所要時間・満足度スコア |
| 観察ポイント | 注目すべき操作・発言・感情の変化 |

**結果レポート** (`report/ux/YYYYMMDD_HHMMSS_usability-result_<対象>.md`)

| 項目 | 内容 |
|---|---|
| エグゼクティブサマリー | 主要な発見事項（3 点以内） |
| タスク別結果 | 完了率・平均時間・エラー箇所 |
| ユーザビリティ問題 | 深刻度（Critical / Major / Minor）付きの問題一覧 |
| 改善提案 | 問題ごとの具体的な改善案 |
| 次のアクション | 優先度付きのアクションリスト |

#### `interaction` — インタラクションデザイン

インタラクション仕様書を作成する。

成果物: `design/04_detailed_design/YYYYMMDD_interaction_<対象>.md`

| 仕様項目 | 内容 |
|---|---|
| トリガー | ユーザー操作（クリック・スワイプ・キー入力等）の定義 |
| フィードバック | 視覚・音・触覚フィードバックの仕様 |
| アニメーション | トランジション種別・デュレーション・イージング関数 |
| マイクロインタラクション | ボタン押下・フォームバリデーション・ローディング表示 |
| エラー状態 | インライン・モーダル・トースト等のエラー表示方針 |
| 空状態 | データなし・初期状態の表示仕様 |
| 状態遷移図 | Mermaid stateDiagram-v2 形式で記述 |

#### `accessibility` — アクセシビリティ改善

WCAG 2.1 Level AA に基づいて診断し、改善レポートを作成する。

成果物: `report/ux/YYYYMMDD_HHMMSS_a11y_<対象>.md`

Grep・Read で以下の観点を検査する。

| 観点 | 確認パターン |
|---|---|
| テキスト代替 | `<img>` に `alt` なし / `alt=""` の不適切使用 |
| キーボード操作 | `tabindex="-1"` によるフォーカス除外・`keydown`/`keyup` ハンドラ不足 |
| コントラスト比 | CSS の `color` / `background-color` の組み合わせ（概算評価） |
| フォーカス管理 | `outline: none` / `:focus { outline: none }` の使用 |
| フォームラベル | `<input>` に対応する `<label>` または `aria-label` なし |
| ARIA 属性 | `role` の誤用・`aria-required`・`aria-describedby` の不足 |
| 見出し構造 | `<h1>`〜`<h6>` の階層スキップ |
| 色のみの情報伝達 | エラーを赤色のみで表示（テキストなし） |
| タイムアウト通知 | セッションタイムアウトの事前警告なし |
| 動画・音声 | 字幕・音声説明の有無 |

重要度付与基準:

| 重要度 | 定義 |
|---|---|
| 🔴 高 | WCAG 2.1 Level A 違反（基本的な操作不能） |
| 🟡 中 | WCAG 2.1 Level AA 違反（一部ユーザーに障壁） |
| 🟢 低 | Level AAA または改善提案（ベストプラクティス） |
