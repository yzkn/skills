# /auto-resume スキル — セッションリミット解除後の自動再開

5 時間のセッションリミットに当たって作業が止まったとき、解除時刻に自動で気づき、中断前の指示を持ったまま再開できる状態にする。`/long-run` が「ジョブの完了」を起点にするのに対し、こちらは**セッション全般の中断**を起点にする（`/long-run` を使っていない普通の作業でも働く）。

## 前提となる制約（設計がこの形になっている理由）

- **リミット解除時刻は事前に取得できない。** トランスクリプト `.jsonl` の `quotaLimits.resetsAt` にだけ記録され、**429 に当たった瞬間のレコードにしか現れない**（平常時のレコードには存在しない。ADR-039・ADR-043 で実測）
- したがって「あらかじめスケジューラに登録して待つ」ことはできず、**429 が起きた瞬間に気づく常駐ウォッチャー**が要る
- **止まった対話セッション（TUI 画面）そのものは復活しない。** 再開の実体は「次にユーザーが開いたときに続きを提示する」か「別プロセスの headless セッションとして継続する」かのどちらか

## 仕組み

SessionStart フック `.claude/hooks/session-resume-check.ps1` が、セッション開始のたびに常駐ウォッチャーを起動する（既に動いていれば何もしない）。ウォッチャーは自セッションの `.jsonl` を追尾し、429 を検出したら解除時刻まで待って発火する。

待機は **独立した 2 系統を併用**する（ADR-039 と同じ考え方。片方が動かなくても他方が拾う）。

| 系統 | 担い手 | 強い場面 | 弱点 |
|---|---|---|---|
| **W1** | 常駐ウォッチャー `_resume-watcher.ps1` が自前で待つ | Claude Code を開いたまま待機する | PC のスリープ・シャットダウンで死ぬ |
| **W2** | Windows タスクスケジューラのワンショットタスク（`ClaudeCodeAutoResume_<yyyymmddhhmmss>`。末尾はロックファイルと同じく解除時刻のローカル時刻） | Claude Code を閉じる・PC がスリープする（`StartWhenAvailable` により復帰後に実行） | 429 を検出する前にウォッチャーが死ぬと登録されない |

二重発火は `.resume/fired/<解除時刻>.lock` の排他生成で防ぐ（先に到達した方だけが実行する）。ファイル名の解除時刻はローカル時刻の `yyyymmddhhmmss` 表記（例: `20260902144825.lock`）。

解除時刻に行うことは 2 通りある。

| 出口 | 動作 | 既定 |
|---|---|---|
| **R2 通知** | OS 通知を出し `.resume/pending.json` を置く。次に Claude Code を開くと SessionStart フックが中断前の指示を提示する | **有効（常に実行される）** |
| **R1 無人 headless 再開** | `claude -p --resume <session-id>` を detach 起動して作業を継続する | 無効（`optin` したときだけ） |

### 状態ファイル

`.resume/`（git 管理外・端末ローカル）。

| ファイル | 役割 |
|---|---|
| `watchers/<session-id>.pid` | 稼働中のウォッチャー（最大 4 本。死んだものは自動で掃除される） |
| `state.json` | 最後に検出した 429（`resetsAt` / `rateLimitType` / セッション ID） |
| `intent.md` | 再開時にやること。明示指定が無ければ**中断前の最後のユーザー指示**を自動で写し取る |
| `pending.json` | 未回収の再開通知。SessionStart フックがこれを読んでコンテキストへ注入する |
| `fired/<yyyymmddhhmmss>.lock` | W1 / W2 の二重発火を防ぐ排他マーカー（ファイル名は解除時刻のローカル時刻） |
| `runs.json` / `optin.json` | R1 の実行回数と設定 |
| `watch.log` / `headless/` | 動作ログと R1 の出力 |

## 使い方

すべて `.claude/scripts/resume-watch.ps1` のサブコマンド。

```
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/scripts/resume-watch.ps1 <サブコマンド>
```

| サブコマンド | 用途 |
|---|---|
| `status` | 稼働中のウォッチャー・検出済みの 429・予約中のタスク・未回収通知を一覧する |
| `intent -Text "<やること>"` | 再開意図を明示的に記録する。**長い作業に入る前に置いておくと、自動抽出より正確に再開できる** |
| `claim` | 再開通知を回収済みにする。**ユーザーへ報告した後に実行する** |
| `optin [-MaxRuns <n>]` | R1（無人 headless 再開）を有効化する（既定 1 回 / 24 時間） |
| `optout` | R1 を無効化する（解除時は通知のみ） |
| `stop` | 稼働中のウォッチャーと予約タスクをすべて停止する |
| `disable` / `enable` | 機構全体を止める / 再開する（`disable` 中は SessionStart でウォッチャーを起動しない） |

`start` / `arm` / `fire` は内部用（フックとウォッチャーが呼ぶ）。手で叩く必要はない。

## Claude Code 向けの手順

1. **中断された作業の通知を受け取ったら**（SessionStart フックがコンテキストへ注入する）、`pending.json` に書かれた中断前の指示を起点に作業を再開する。`headless=true` の場合は `.resume/headless/` の最新ログを先に読み、**同じ作業を二重に行わない**
2. **ユーザーへ報告し終えてから** `claim` を実行する。報告より先に実行すると通知だけが消えて報告が漏れる
3. **リミットに当たりそうな長い作業を始めるとき**は `intent -Text "<再開時にやること>"` を置く。自動抽出は「最後のユーザー発話」であり、複数ターンにまたがる作業の意図までは表せない

## 遵守事項

- 【要指示】**R1（無人 headless 再開）の有効化はユーザーの明示的な指示がある場合のみ行う。** 無人セッションは承認プロンプトを出せないため、`optin` は「承認ゲートが効かない時間帯を作る」ことと同義である。Claude Code の判断で `optin` してはならない
- 【絶対禁止】**無人再開を禁止事項の回避手段にしてはならない。** headless セッションでも `git push`・証跡ファイルの編集などの【絶対禁止】は解除されない（`.claude/rules/prohibition-levels.md`）
- **`--dangerously-skip-permissions` を使わない。** R1 は通常の権限モードで起動し、承認が要る操作に当たったら停止してログに残す設計である
- R1 は **`rateLimitType` が `five_hour` のときだけ**動く。週次上限（`five_hour` 以外）では通知のみに落とす。無人再開で週次の枠を消費し尽くさないための歯止めである
- 再開回数は既定で **24 時間あたり 1 回**。上限に達したら通知のみになる

## 制約・未検証

- **Windows 専用。** タスクスケジューラ（`Register-ScheduledTask`）と Windows Forms の通知に依存する。非管理者権限で登録・削除できることは実測済み
- **ウォッチャーは 90 分アイドルで終了する**（トランスクリプトが更新されなくなったら、そのセッションは終わったとみなす）。ただし 429 検出後の待機中はアイドル判定を行わない
- **429 を人為的に再現できない**ため、検出から発火までの一連は**模擬 429 レコードを注入した自己テストで検証している**（実際の 429 レコードの構造は 3 セッション分の実データで確認済み）
- **`claude -p --resume` が対話セッションと同じトランスクリプトへ書き込むかは未検証**（ADR-039 から引き継いだ未確定事項）。R1 を使う場合、再開後の記録がどこに残るかを `.resume/headless/` のログで確かめること
- PC のシャットダウン中に解除時刻を過ぎた場合、W2 は次回起動時に実行される（`StartWhenAvailable`）。W1 は失われる
