# ux-writing — UI コピーの執筆・レビュー

UI 上の短いテキスト（ボタン・エラー・空状態・確認ダイアログ・通知・ラベル）を、一貫したボイス＆トーンで執筆・レビューするスキル。

> 出典: [plugin87/ux-ui-agent-skills](https://github.com/plugin87/ux-ui-agent-skills)（MIT License）を自己完結化して収録。参照ファイルは英語原文のまま。**ユーザーへの応答・成果物のコピーは日本語**で作成する（英語 UI 向けの依頼を除く）。

## 手順

1. [voice-tone.md](voice-tone.md) を Read する（ボイス原則・トーンスペクトラム・各種公式・マイクロコピーパターン・インクルーシブ言語・出荷前チェックリスト）
2. ユーザーの感情状態にトーンを合わせる（オンボーディング / 成功 / 日常操作 / エラー / 破壊的操作）。**ストレスが高い場面ほど平易な言葉**を使う
3. 公式を適用する:
   - **ボタン**: 動詞を先頭に置き、結果を名指しする
   - **確認ダイアログ**: 確認ボタンは操作と対象を復唱する —「アカウントを削除」であり「OK」「はい」「確認」ではない。タイトルが問い（「アカウントを削除しますか？」）、ボタンが同じ語で答える。キャンセルは「キャンセル」のまま。不可逆・重大な操作には **type-to-confirm**（対象名の入力）を要求する（WCAG 3.3.4 / 3.3.6）
   - **エラー**: 何が起きた → なぜ → どうすれば直るか（行き止まり禁止・エラーコードやスタックトレースの露出禁止。本プロジェクトの「エラーメッセージの品質基準」とも一致）
   - **空状態**: 提供価値 → 最初のアクション
4. メカニクスを守る: ユーザーを責めない・プレースホルダーでなくラベル・色や位置だけに依存した指示をしない・数字は数字で書く（英文の場合は sentence case・ALL CAPS 禁止も適用）
5. [voice-tone.md](voice-tone.md) 末尾の 10 項目出荷前チェックリストを全行に適用してから完了とする

## 日本語 UI 特有の補足

- 敬体（です・ます）を基本とし、プロダクト全体で文体を統一する
- ボタンは体言止めまたは動詞終止（「保存」「削除する」）でプロダクト内で統一する
- 半角英数字と全角文字の間のスペース有無をプロダクト内で統一する

## 出力・検証

- 最終コピー（または赤入れレビュー）を提示する。文字数制限がある UI ではその範囲に収める
- 翻訳可能性を確認する（文字列連結で文を組み立てない）。多言語・RTL 対応が論点になる場合は [i18n-rtl.md](i18n-rtl.md) を Read する
- プロダクト全体の文言一覧を成果物にする場合は `design/04_detailed_design/` に保存する。用語の統一が必要な場合は `/domain-modeling` に接続する
