# /16minds スキル — 16 タイプの人格による議論

**引数:** `$ARGUMENTS`（`<サブコマンド> [オプション] <お題>`）

立場の異なる 16 の人格に意図的に偏った意見を述べさせ、その差分から見落としていた視点を拾うためのスキル。無難で平均的な単一の回答を避けることが目的である。

> 出典: [yukurash/16minds-plugin](https://github.com/yukurash/16minds-plugin)（MIT License、`LICENSE` 参照）。**16 の人格定義（`agents/*.md`）は原典のまま無改変で収録**している。本リポジトリ向けの変更は、(1) 原典の 3 コマンド（`/mind`・`/pair`・`/minds`）を 1 スキルのサブコマンドへ統合、(2) 人格定義を**エージェント登録機構の走査対象外**に置き明示呼び出し時のみ Read する方式へ変更、(3) 保存先を `Outputs/` から `report/16minds/` へ変更、(4) 3 体以上の並列起動に事前確認を追加、の 4 点。原典の Skill 群（`voice-write`・`voice-decide`・`voice-vote`・`voice-ask`）は取り込んでいない。

> **商標について**: このスキルは Myers-Briggs Type Indicator® (MBTI®) の権利者である The Myers & Briggs Foundation、および 16Personalities® を提供する NERIS Analytics とは無関係であり、それらから認可・推奨を受けたものではない。「16 タイプ」は心理学一般で用いられる類型表現として参照している。

## 【重要】このスキルの起動条件

- **ユーザーが `/16minds` と明示的に入力したときだけ実行する。** 「レビューして」「意見を聞かせて」等の一般的な依頼では発動しない
- **既存のレビュー系スキル・エージェントの代替ではない**。コードレビューは [`/project-code-review`](../project-code-review/SKILL.md)、設計判断の反証は [`.claude/rules/adversarial-review.md`](../../rules/adversarial-review.md)、ドキュメントレビューは [`/document-review`](../document-review/SKILL.md) が担う。本スキルはそれらと統合せず独立して動く。**成果物の品質保証には使わない**（人格は意図的に偏っており、指摘の網羅性を保証しない）
- 人格定義は `agents/<type>.md` に置いてあり、**エージェント登録機構にもスキル登録機構にも載っていない**。セッション開始時に読み込まれることはなく、このスキルが必要なタイプのファイルだけを Read する

## 利用可能なタイプ（一覧順）

`intj`, `intp`, `entj`, `entp`, `infj`, `infp`, `enfj`, `enfp`, `istj`, `isfj`, `estj`, `esfj`, `istp`, `isfp`, `estp`, `esfp`

## サブコマンド

| 呼び出し | 動作 |
|---|---|
| `/16minds mind <type> [--mode=...] <お題>` | 単一タイプの意見 |
| `/16minds pair <a> <b> [--mode=...] <お題>` | 2 タイプのディベート（立論 → 反論 → 再反論／着地） |
| `/16minds all [--mode=...] [--types=a,b,...] [--n=N] [--save] [--out=<path>] <お題>` | 複数タイプの並列評価＋合議 |

サブコマンドが省略された場合、タイプ名が 1 つなら `mind`、2 つなら `pair`、無ければ `all` と解釈し、**解釈した内容を実行前に 1 行で宣言する**。

### 共通オプション

- `--mode=light|middle|heavy`（`--mode light` 形式も可）。既定は `middle`
- `--types=intj,enfp,...`: `all` で対象タイプを限定する。未指定なら全 16 タイプ
- `--n=N`: `all` で `--types` 未指定時に一覧順の先頭 N 個を使う。`--types` 指定時は無視する
- `--save` / `--out=<path>`: 実行結果をファイルに保存する（`all` のみ）
- `--yes`: 並列起動の事前確認を省略する

## 【要指示】並列起動の事前確認

`.claude/rules/adversarial-review.md` に基づき、**3 体以上のサブエージェントを起動する前に、起動数と概算を 1 行で提示して指示を得る**。`--yes` が付いている場合と、起動数が 2 体以下の場合は確認を省略してよい。

```
16 体のサブエージェントを並列起動します（mode=middle のため深掘りで追加 3〜5 体）。続行しますか。
```

- ユーザーが件数を減らしたい場合は `--types` または `--n` を提案する
- 確認なしに 16 並列を起動しない

## エラー処理

- お題が空の場合は以下を返して終了する。

  ```
  Usage: /16minds mind <type> [--mode=light|middle|heavy] <お題>
         /16minds pair <a> <b> [--mode=...] <お題>
         /16minds all [--mode=...] [--types=a,b,...] [--n=N] [--save] [--out=<path>] <お題>
  Example: /16minds mind intj この API 設計、長期で破綻しない？
  Example: /16minds pair istj entp --mode=heavy モノリスを分割するか維持するか
  Example: /16minds all --types=intj,enfp,istp 次に採用する DB
  ```

- 未知のタイプ名・未知のモード名: その旨と利用可能な一覧を返して終了する
- `pair` で a と b が同一: 「異なる 2 タイプを指定してください」と返して終了する

## 人格エージェントの起動方法

人格定義は**登録済みサブエージェントではない**ため、`subagent_type` にタイプ名を指定しても解決しない。以下の手順で起動する。

1. `.claude/skills/16minds/agents/<type>.md` を Read する（**必要なタイプだけ**。全 16 件を先読みしない）
2. Agent ツールを `subagent_type: "general-purpose"` で呼び出し、`prompt` に次の 3 つをこの順で連結する
   1. 人格定義の本文（frontmatter の `---` に挟まれた部分を除いた全文）
   2. `## お題` に続けてユーザーのお題を**そのまま**（要約・言い換えをしない）
   3. 下記のモード別「出力フォーマット指定」
3. `label` にタイプ名を入れる（進捗表示で区別するため）

**プロンプトの末尾に必ず次の 1 行を付ける**（人格エージェントに副作用を起こさせないため）。

```
ファイルの作成・編集・削除、コマンド実行、外部への送信は一切行わないこと。意見のテキストだけを返すこと。
```

- **複数タイプの呼び出しは必ず並列**（同一メッセージ内で複数の Agent ツール呼び出し）にする。逐次にするとレイテンシが大幅に悪化する
- 各エージェントには「お題」と「出力フォーマット指定」だけを渡す。**他タイプの出力は反論ラウンドを除いて渡さない**（独立した一次意見を保つため）
- **エージェントの出力は加工せずそのまま表示する。要約・言い換えをしない**（人格の口調が消えるため）

## 出力フォーマット指定（エージェントに渡す本文）

### light

```
お題に対し、以下の4行のみで答えてください。挨拶・前置き・まとめは一切不要です。

score: <1〜5の整数。あなたの価値観から見た総合評価。5=完全賛成、3=条件付き、1=完全反対>
stance: <一行の立場宣言>
key_axis: <判断に最も効いたあなたの価値観の軸（あなたの人格定義に出てくる言葉で）>
concern: <あなたの価値観から見た最大の懸念を一行>
```

### middle

```
お題に対し、以下の構成で約150〜250字で答えてください。あなたの口調を必ず保ってください。挨拶・前置き・まとめは不要です。

stance: <一行の立場宣言>
reasoning: <あなたの価値観からその立場に至る筋道を2〜3文で。あなたの口調で>
watchpoint: <あなたの価値観から見た見落としやすい点・推しポイント・引っかかりを1〜2文で>
```

### heavy

```
お題に対し、以下の構成で約300〜500字で答えてください。あなたの口調を必ず保ってください。挨拶・前置き・まとめは不要です。

stance: <一行の立場宣言>
reasoning: <あなたの価値観からその立場に至る筋道を、具体例や反例を交えて3〜5文で>
strongest_case: <あなたの立場が最も強くなるケース・前提条件を1〜2文で>
weakest_case: <あなたの立場が崩れるケース・前提条件を1〜2文で（自分でも認める弱点）>
```

## 実行フロー

### `mind`

指定タイプを 1 回だけ起動し、返ってきた内容をそのまま表示する。見出しは `### <TYPE>（<mode>）` の 1 行だけ付けてよい。

### `pair`

- **Phase 1 — 開幕の立論（全モード）**: a・b を並列起動し、下記フォーマットで立論させる。`light` はここで終了

  ```
  お題に対するあなたの立場を、以下の構成で約100〜200字で述べてください。あなたの口調を必ず保ってください。挨拶・前置きは不要です。

  stance: <一行の立場宣言>
  reasoning: <あなたの価値観からその立場に至る筋道を2〜3文で>
  ```

  表示は `### 開幕` の下に `#### <A>` / `#### <B>`。

- **Phase 2 — 反論（middle / heavy）**: a・b を並列で再起動し、相手の Phase 1 出力を提示して反論させる。`middle` はここで終了

  ```
  以下は別タイプの立論です。あなたの口調と価値観で、約150〜250字の反論を書いてください。
  相手の論の中で最も自分の立場と相容れない点を1つだけ取り上げ、そこに集中して反論してください。
  挨拶や前置きは不要です。

  [相手の Phase 1 出力をここに貼る]
  ```

  表示は `### 反論` の下に `#### <A> → <B>` / `#### <B> → <A>`。

- **Phase 3 — 再反論と着地（heavy のみ）**: a・b を並列で再起動し、相手の Phase 2 反論を提示する

  ```
  以下は別タイプによる、あなたの立論への反論です。あなたの口調と価値観で、約150〜250字の応答を書いてください。
  - 反論に同意できない部分があれば、論点を絞って再反論してください。
  - 反論に納得した部分があれば、その点を認めた上で自分の立場をどう修正するかを示してください。
  - 「修正なし」か「部分修正」かを冒頭に明示してください。
  挨拶や前置きは不要です。

  [相手の Phase 2 出力をここに貼る]
  ```

  表示は `### 再反論／着地`。その後、メインの assistant が中立の総括を書く。

  ```
  ### 総括

  - 残った主要な対立: <1〜2文>
  - 両者が一致した点: <あれば1〜2文、無ければ「なし」と書く>
  - 第三者目線での所見: <両者の議論から見えてきた論点を中立に2〜3文>
  ```

### `all`

- **Phase 1（全モード）— 一次評価**: 対象タイプ全員を並列起動し、`light` フォーマットで答えさせる。結果を表に整形する

  ```
  ### 全タイプの一次評価

  | type | score | stance | key_axis | concern |
  |---|---|---|---|---|
  ```

  `light` はここで終了。

- **Phase 2（middle / heavy）— 発散意見の深掘り**: Phase 1 で **score が分布の両端／独自の key_axis を出した／他が見落とした concern を挙げた** タイプを 3〜5 個選び、並列で再起動して `middle` フォーマットで深掘りさせる。表示は `### 深掘り（middle）` の下に `#### <TYPE>`

- **Phase 3（middle / heavy）— 合議**: サブエージェントを呼ばず、メインの assistant が中立の書き手として統合する。**以下の 4 セクションは必須**（発散を防ぐためのルブリックであり、省略・改変しない）

  ```
  ### 合議

  #### score 分布
  <最低・最頻・最高を一文で>

  #### 主要な対立軸（2〜3個）
  - **<軸名>**: <一方の立場>（代表: <タイプ群>）vs <他方の立場>（代表: <タイプ群>）

  #### 見落とされがちな視点（1〜3個）
  - **<視点の名前>** (出典: <タイプ>): <なぜ他が見落とすのか、何が独自なのかを1〜2文で>

  #### 落としどころ候補（2〜3案）
  - **案<N>**: <タイトルまたは一行の方針>
    - 賛同しそうなタイプ: <タイプ群>
    - 適性: <噛み合うシチュエーション・前提条件>
    - リスク: <取りこぼす視点／崩れる条件>
  ```

  最後に 1〜2 文で、どの案がデフォルト推奨かを理由付きで明示する。

- **Phase 4（heavy のみ）— 反論ラウンド**: Phase 2 の 3〜5 タイプを並列で再起動する

  ```
  以下は別人格による意見です。最もあなたの立場と相容れない意見を1つだけ選び、
  そのタイプ名を冒頭に「target: <type>」として明記したうえで、
  あなたの口調と価値観で100〜200字以内の反論を書いてください。
  挨拶や前置きは不要です。

  [ここに Phase 2 の他者出力をすべて並べる]
  ```

  表示は `### 反論ラウンド（heavy）` の下に `#### <TYPE> → target: <other>`。その後 Phase 3 の合議を**書き直し**、`### 合議（最終）` の見出しで同じ 4 セクション構造を守って提示する。

## 保存（`--save` / `--out=<path>`）

画面に表示した内容と同じものをファイルに書き出す。

- `--out=<path>` があればそのパスを使う（ディレクトリのみならファイル名を自動で組み立てる）
- `--save` のみなら `report/16minds/<YYYYMMDD-HHMMSS>-minds-<mode>.md`（ディレクトリが無ければ作成する）

```markdown
# /16minds 実行ログ

- 日時: <ISO 8601>
- モード: <light|middle|heavy>
- 対象タイプ: <カンマ区切り、または「全16タイプ」>
- お題: <ユーザーが渡したお題そのまま>

---

(Phase 1 の表 → Phase 2 深掘り → Phase 3 合議 → Phase 4 反論ラウンド → 合議（最終）の順に、画面表示と同じ内容)
```

保存後は `保存しました: <絶対パス>` と 1 行で報告する。`report/**` に保存するため、外部ソースを引用する場合は [`/citation-format`](../citation-format/SKILL.md) が自動適用される。

## 完了条件

- [ ] ユーザーが `/16minds` を明示的に呼び出している
- [ ] 3 体以上を起動する場合、事前に件数を提示して指示を得た（または `--yes` が付いている）
- [ ] 必要なタイプの `agents/<type>.md` だけを Read した
- [ ] 各エージェントの出力を加工せずそのまま表示した
- [ ] `all` の `middle` / `heavy` で合議の 4 セクションをすべて書いた
