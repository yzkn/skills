# コード品質ルール — 詳細編（常時ロードしない）

`.claude/rules/code-quality.md` から分離した一般知識部分。SOLID・DRY 等の広く知られた原則と汎用の品質目安をまとめている。**原則自体の適用は常に必須**であり、内容を確認する必要があるとき（コードの生成・修正・レビューに着手するとき、プロファイルが標準のとき）に Read する。

## 基本設計原則（一言要約）

| 原則 | 要約 |
|---|---|
| **SRP** (単一責任) | クラス・モジュールの変更理由は 1 つだけ |
| **OCP** (開放閉鎖) | 拡張に開き、修正に閉じる。型判定の if/switch 連鎖を増やさない |
| **LSP** (リスコフ置換) | 子クラスは親クラスと無条件に置き換え可能 |
| **ISP** (インターフェース分離) | 使わないメソッドへの依存を強制しない |
| **DIP** (依存性逆転) | 上位・下位モジュールとも抽象（インターフェース）に依存する |
| **DRY** | 同じ知識を 2 箇所以上に書かない |
| **KISS** | 「賢い」コードより「読みやすい」コードを選ぶ |
| **YAGNI** | 今必要な機能のみ実装する。将来の予測で実装しない |
| **Fail Fast** | エラーは早い段階で明確に報告する。サイレントフォールバック・握りつぶし禁止 |

## コード品質基準

| 基準 | 目安 |
|---|---|
| 関数の責任 | 1 つのみ |
| ネスト深度 | 3 階層まで |
| 関数行数 | 50 行以内を目安 |
| コメント | WHY（なぜ）を書く。WHAT（何を）はコードで示す |
| 型安全性 | `any`・型アサーション乱用は禁止 |
| エラーハンドリング | `catch (e) {}` 等の握りつぶしは禁止 |
| 依存方向 | 上位レイヤーが下位レイヤーを知らない構造を維持 |

## 実装前の判断順序（書く前に減らす）

YAGNI・KISS を実装の場面で具体化した手順。**コードを書く前に上から順に問い、最初に「はい」になった段で止める。**

| 順 | 問い | 「はい」のときの対応 |
|---|---|---|
| 1 | そもそも不要ではないか | 実装しない。理由を依頼者に返す |
| 2 | リポジトリ内に同じことをするコードがあるか | 既存コードを使う（DRY） |
| 3 | 言語の標準ライブラリで足りるか | 標準ライブラリを使う |
| 4 | フレームワーク・プラットフォームの機能で足りるか | その機能を使う |
| 5 | 導入済みの依存パッケージで足りるか | それを使う（**新規の依存追加は【要指示】**。`.claude/rules/external-resources.md`） |
| 6 | 数行で書けるか | 数行で書く |
| 7 | — | 要件を満たす最小の実装を書く |

- **意図的に簡略化した箇所はコメントで明示する**（何を省き、どうなったら作り直すか）。例: `// 簡略化: 件数が 1,000 を超えたらページングに置き換える`。後から読んだ人が「手抜き」と「判断」を区別できるようにする
- **次の領域では簡略化しない**: 信頼境界での入力検証・認証と認可・データの消失や破損につながる処理・エラー処理（Fail Fast）・秘密情報の扱い・アクセシビリティ。短く書くことより正しさを優先する

> 出典: DietrichGebert/ponytail（MIT）の判断ラダーと「簡略化の明示」の着想を、本ファイルの原則に合わせて書き下ろした。プラグイン本体・フックは導入していない。

## 着手前の確認（確かめられるまで書き始めない）

上の判断順序で「書く」と決まった後、最初の 1 行を書く前に次を確かめる。**1 つでも答えられない項目があれば、実装に入らずに不足している情報をユーザーに示す。** 推測で埋めて書き始めない。

| 確認すること | 確かめ方 |
|---|---|
| 同じことをするコードがリポジトリに無いか（判断順序の 2 段目） | Grep で関数名・処理内容の語を探した結果を示す |
| 既存の構成・規約に沿った置き場所と書き方か | 近いモジュールを 1 つ読み、構成・命名・エラー処理をそろえる |
| 使う API・設定の書き方を公式ドキュメントで確かめたか | `/source-driven-development` の手順で裏取りする |
| （バグ修正の場合）根本原因を特定したか | `/systematic-debugging`。症状だけを抑える修正に入らない |

- 確認の結果は着手前に短く報告する（何を確かめ、何が未確認か）
- 軽微な変更（typo の修正・機械的な置換）では省略してよい

> 出典: [SuperClaude-Org/SuperClaude_Framework](https://github.com/SuperClaude-Org/SuperClaude_Framework)（MIT License、評価時の commit `fe68862`）の `confidence-check` の確認項目を書き下ろした。重み付けの数値スコアと閾値は、根拠が示されていないため取り込んでいない（ADR-058）。
