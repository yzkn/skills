# /explainer-html スキル — 自己完結 HTML 解説文書

**引数（説明対象・入力ファイル・出力名）:** $ARGUMENTS

概念・仕組み・調査結果を、**単一ファイルで完結する HTML 文書**として作成・編集する。ビルド不要でブラウザが直接描画でき、オフライン・社内プロキシ下・Artifact 共有のいずれでも同じ見た目になる。

> 出典: [mathbullet/skills](https://github.com/mathbullet/skills)（MIT License、`LICENSE` 参照）の `html` スキルを本リポジトリ向けに作り直したもの。コンポーネント体系と配色（背景 `#FAF9F6` / 白地＋黒罫線 / リンク青とアクセント赤の 2 色）は原典を土台にしつつ、**(1) Web フォント・MathJax・highlight.js の CDN 4 本をすべて排して自己完結化**、**(2) `prefers-color-scheme` によるダークモード対応と日本語フォントスタックを追加**、**(3) 数式を MathJax から MathML へ、ハイライトを highlight.js から pandoc skylighting へ置換**、**(4) macOS 専用の `render-pdf.sh` は移植せず `@media print` のみ対応**、と変更した。原典が併用を推奨する外部 Gist 2 本は参照しない（`.claude/rules/external-resources.md`）。

## 隣接スキルとの棲み分け（先に確認する）

| 依頼の実体 | 使うもの |
|---|---|

| Markdown の解説文書の**書き方**（用語表・粒度・構成） | [`/explain` 相当の規約](../../rules/design-docs.md)（Mermaid 規約）＋ `/ghostwriter` |

| プロジェクトの**現在状況**を可視化する | [`/project-dashboard`](../project-dashboard/SKILL.md) |

## 成果物の規約

- **外部リクエスト 0 件**。CSS・JS・フォント・画像をすべて単一 HTML に内包する。CDN・Web フォント・外部スタイルシートを読み込まない
- 画像を含める場合は base64 データ URI として埋め込む
- ファイル名は `{yyyymmdd}-{内容を表すケバブケース}.html`。**既存ファイルの更新では名前を変えない**
- 出力先は、指定があればそれに従う。指定がなければ `report/explainer/` に置く（ディレクトリが無ければ作成する）。設計書に添える場合は `design/` の該当フェーズフォルダに置く
- `report/**`・`design/**` に出力する場合、引用と典拠の書式は [`/citation-format`](../citation-format/SKILL.md) が自動適用される

## デザインシステム

**[`assets/template.html`](assets/template.html) を土台にコピーして書く。** CSS はこのファイルの `<style>` に内包済みで、これが唯一の正本である。使えるコンポーネントのマークアップは [`references/components.md`](references/components.md) を Read して確認する。

実際の描画は [`assets/sample.html`](assets/sample.html) をブラウザで開いて確認できる（全コンポーネントを 1 ページに並べた見本。ダーク/ライトを切り替えるボタン付き）。**CSS を変更したときは `template.html` の `<style>` を直し、次のコマンドで見本へ反映する**（見本側の CSS を直接編集しない）。

```sh
python .claude/skills/explainer-html/scripts/build_sample.py          # 反映する
python .claude/skills/explainer-html/scripts/build_sample.py --check  # ずれの有無だけ調べる（一致=0 / 不一致=1）
```

主要規則:

- 背景は `#FAF9F6`、部品は白地・黒罫線・角丸。ダーク時は CSS 変数が自動で切り替わる
- 有彩色はリンク青 `#2990DA` とアクセント赤 `#D63A2F` に限る。**赤い強調は 1 ページ 1 箇所まで**
- シンタックスハイライトとコード差分の色は、意味を区別する機能色としてこの制限の対象外
- 絵文字・矢印文字を図記号として使わない。必要な記号はインライン SVG で描く
- 表は短い対応関係に使い、**3 列までを基本**とする。横に長い表は `.mb-table-scroll` で囲み、ページ本体を横スクロールさせない
- **ページ固有の `<style>` は図の配置調整など最小限**にとどめる。`references/components.md` に無いクラスを新規に作らない
- 配色そのものを変えたい場合は独断で変えず、`/ui-ux-pro-max`・`/anti-slop-review` の観点を踏まえて提案する

## 読み手を決める

説明は読み手が**まだ知らないこと**だけを書く。書き始める前に読み手を 1 人（または 1 つの役割）に絞り、次の 3 区分で書き出す。

| 区分 | 書くもの |
|---|---|
| 依頼文にあった | 依頼文・資料から**確認できた事実だけ**（役割・使っている技術・読んだ後に判断したいこと） |
| 推測した | それ以外のすべて。**理由を添える**。もっともらしくても事実の欄に移さない |
| 未確認 | 答えで資料の主軸が変わる質問（最大 5 問） |

- 聞ける相手なら質問して止まる。答えが得られないときは推測のまま書き進め、**3 区分を文書冒頭の「想定読者」と報告の両方に書く**（黙って決めない）
- 読み手が既に知っている事柄は削る。用語リストにも載せない
- 3 区分はファイルとして保存しない。実在の人物についての推測をリポジトリに残さないため、文書内の「想定読者」に留める

> 出典: [mizchi/explainer](https://github.com/mizchi/explainer)（MIT License）の `explainer` スキルの「ペルソナ」「やってはいけないこと」の考え方を書き下ろした。ペルソナファイルの保存・vlmkit / D2 / Playwright による検証は取り込んでいない（ADR-057）。

## 文書構成

```
0. 想定読者（上記の 3 区分）
1. 用語リスト（サイドバー）
2. 背景 — なぜこれが必要か、どの問題に対処するか
3. 本論 — 仕組み。図を含む
4. 具体例 — コマンド・手順・実例
5. 補足・限界・関連事項
```

- `h1` とリード文の後に `.mb-toc` の目次を置き、各 `h2` に対応する `id` を付ける
- **専門用語は本文で使う前に用語リストで 1〜2 文で定義する**。広く知られた製品名・基盤コンポーネントも定義する。複合語は構成する単語も個別に立てる
- 主語・目的語・動詞を省かない。「A は B を使って X する」と書くなら、A が何で、なぜ X に A が要るかまで書く
- 仕組みは一般形で先に述べ、固有名の実例は「X の場合は〜」として後に結ぶ。単一の固有名詞に説明全体を寄せない
- 一方向の単純な手順を、必要もなく図にしない
- **主張には根拠の区分を付ける。** 区分は「確かめた」（実行・再現・原典で確認した）・「読み取れる」（コードや資料から読めるが、実行はしていない）・「見解」（経験則や設計上の判断）の 3 つ。区分は各主張の直後に短いラベルで書き、「読み取れる」を「確かめた」に格上げしない
- **本文に載せるコードはファイルから写す。** 記憶や要約から書き起こさない。`パス:行` で参照した箇所は、下記の検証 4 で実在を確かめる

> 出典: [init-co-jp/diff-tour](https://github.com/init-co-jp/diff-tour)（MIT License、評価時の commit `3cde297`）の根拠ラベルと「LLM が出したファイル・行の参照を機械的に検証する」考え方を書き下ろした。ツール本体（Go 製の TUI）は導入していない（ADR-058）。

## コード

シンタックスハイライトは **pandoc（3.10 導入済み）の skylighting** で生成し、結果の HTML をそのまま埋め込む。JS は読み込まない。

```sh
# 断片を書いた tmp.md（```python … ``` のフェンス付き）を HTML 化する
pandoc -f markdown -t html tmp.md
```

- 出力の `<div class="sourceCode">…<span class="kw">…` をそのまま本文に貼る。`template.html` の CSS が `kw` / `co` / `st` / `fu` 等の機能色を定義済み
- 出力に含まれる `<a href="#cb1-1" aria-hidden="true">` は空のアンカーで、表示・レイアウトには影響しない。そのまま残してよい
- ハイライトが不要な場合は `<pre><code>…</code></pre>` で足りる
- 独自の色付けを `<style>` で足さない
- **コマンドの出力・実行結果は打ち直さない。** 実際に実行した出力を貼り、書き終えたら再実行して本文と一致することを確かめる。実行できなかった出力には「未実行」と明記する

## 数式

MathML で書く。ブラウザ（Chrome 109+ / Edge 109+ / Firefox / Safari）がネイティブに描画するため外部ライブラリは不要。

```sh
# LaTeX を書いた tmp.md を MathML に変換する
pandoc -f markdown -t html --mathml tmp.md
```

- pandoc の出力は `<annotation encoding="application/x-tex">` に LaTeX 原文を含む。**その値を親要素の `data-latex` 属性にも入れる**と、テンプレート内蔵の JS が LaTeX コピーボタンを自動で付ける
- ディスプレイ数式は `.mb-math-block`、インライン数式は `.mb-math-inline` で囲む
- ベクトル・行列は太字（`mathvariant="bold"`）。スカラー・添字・集合名は装飾しない
- 数式をコードブロックに入れない

## 図

- **図を記憶から描かない。** 描く前に、図に載せる要素と関係（何が何を呼ぶ・どこにデータがあるか）を出典付きで箇条書きにした事実シートを作り、描いた図をそれと 1 項目ずつ照らす。食い違ったら図を直す
- 自作図は**インライン SVG**。アスキーアートを使わない。黒一色の線画を基本とし `.mb-figure-frame` に載せる
- 線色は `stroke="currentColor"` を使う。ダークモードで線が消えなくなる
- ノードが多い場合は縦方向を優先し、矢印が交差する構成を避ける
- **原典に重要な図がある場合は模倣図を作らず、出所を明示して原典の図を引用する**
- **サービス・製品のアイコンは、ライセンスを確認したうえで `<img src="data:image/png;base64,...">` の形で埋め込む**（`.claude/rules/third-party-licenses.md`）。**URL 参照は禁止**（本スキルは外部リクエスト 0 件が要件）

### 原典の図表を引用する（PDF から切り出す）

論文・規格書・受領資料の図表は、手で描き直さず PDF から画像として切り出す。転記ミスと元レイアウト（太字・下線・色分け）の欠落を防ぐため。

```sh
python .claude/scripts/pdf/extract_figures.py <PDF パス> [--out DIR] [--dpi N]
```

- `Figure N` / `Table N` のキャプション直上の描画領域を 300 dpi でクリップレンダリングし、既定で `report/figures/` に PNG を書き出す。抽出一覧は同ディレクトリの `*-manifest.json`
- PyMuPDF はこの端末に導入済みのため `python` で動く（Windows PowerShell 上での実行を確認済み）。未導入の端末では `uv run` に切り替える
- 切り出した画像は **base64 データ URI として HTML に埋め込む**（自己完結の要件）
- 画像内のキャプションは原文のまま残るため、訳文は画像の下に別段落で添える
- 取りこぼし・余白過多がある場合は `--dpi` を上げるか対象を個別調整する。手描き再構成へ戻さない

## 実行手順

1. **入力と出力先の確定** — 説明対象・読み手・出力パスを宣言する。既存ファイルの更新なら現物を Read してから編集する
2. **読み手を決める**（上記）— 3 区分を書き、読み手の既知を除いた「書くべき差分」を決める
3. **用語の洗い出し** — 本文で使う専門用語のうち読み手が知らないものを列挙し、用語リストの定義を先に書く
4. **[`references/components.md`](references/components.md) を Read** し、使うコンポーネントを決める
5. **[`assets/template.html`](assets/template.html) をコピー**して内容を流し込む
6. **コード・数式・図を生成**して埋め込む（上記各節）
7. **検証**（下記）
8. **報告** — 出力パス・想定読者の 3 区分・構成・検証結果を伝える。検証結果は**どの検査が、どの範囲で通ったか**を書き、「問題なし」に丸めない

## 検証（スクリプトで機械的に行う）

書き込み後、以下をすべて確認する。**目視で済ませない。**

```sh
F=<出力した HTML のパス>
# 1. 外部リソースの読み込みが 0 件であること（何も出力されなければ合格）
grep -nEi 'src="https?:|<link[^>]+href="https?:|@import|url\(\s*["'"'"']?https?:' "$F"
# 2. 0 バイトでないこと・行数
wc -c "$F"
# 3. 目次のアンカーが実在する id を指していること
grep -oE 'href="#[^"]+"' "$F" | sed 's/href="#\(.*\)"/\1/' | sort -u > /tmp/anchors.txt
grep -oE 'id="[^"]+"' "$F" | sed 's/id="\(.*\)"/\1/' | sort -u > /tmp/ids.txt
comm -23 /tmp/anchors.txt /tmp/ids.txt
# 4. 本文の「パス:行」参照が実在すること（リポジトリのルートで実行。何も出力されなければ合格）
sed -E 's#https?://[^ "<>]*##g' "$F" | grep -oE '[A-Za-z0-9_./-]+\.[A-Za-z0-9]+:[0-9]+' | sort -u | while IFS=: read -r p l; do
  { [ -f "$p" ] && [ "$(wc -l < "$p")" -ge "$l" ]; } || echo "NG $p:$l"; done
```

- 検証 1 で `xmlns="http://www.w3.org/..."` は名前空間宣言であり**ヒットしない**（リソース読み込みではない）。本文中の `<a href="https://…">` も外部送信ではないためヒットしない
- 検証 3 の `comm` が何か出力したら、目次のリンク先が存在しない。修正する
- 検証 4 の `NG` は、ファイルが無いか、行番号がファイルの行数を超えている。参照を直す。行が存在しても指す内容が正しいとは限らないため、NG が無くても引用部分はファイルと照らす
- ライト／ダークの両方で成立しているかは、`<html data-theme="dark">` を一時的に付けて描画確認する（[`assets/sample.html`](assets/sample.html) には切り替えボタンがあり、OS 設定を変えずに両方を見られる）
- CSS を触った場合は `python .claude/skills/explainer-html/scripts/build_sample.py --check` が 0 を返すことも確認する
- 検証結果は**終了コードと要点だけ**を報告に載せる（全文をコンテキストに載せない）
