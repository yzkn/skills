# Power Fx / Canvas App のリファクタリング（code-refactor 補助ファイル・常時ロードしない）

`/code-refactor` の Step 1 で対象が `.pa.yaml` / `.fx.yaml` / Power Fx 数式のときに Read する。汎用の手順・承認ゲート・対象外の定義は `SKILL.md` が正。**着手前に `SKILL.md`「Power Platform 案件での注意」を必ず確認する**（スキーマ名の改名禁止・適用範囲の合意・50 行基準の非適用・テスト不在時の扱い）。

## 1. 命名規則

| 対象 | 規則 | 例 |
|---|---|---|
| コントロール | 型の略称（小文字 3 文字）+ PascalCase | `btnSubmit`、`lblUserName`、`galOrders`、`txtSearch`、`icoRefresh` |
| 画面 | PascalCase + `Screen` 接尾 | `HomeScreen`、`OrderDetailScreen` |
| グローバル変数（`Set`） | `gbl` + PascalCase | `gblCurrentUser` |
| コンテキスト変数（`UpdateContext`） | `loc` + PascalCase | `locSelectedItem` |
| コレクション（`Collect` / `ClearCollect`） | `col` + PascalCase | `colOrderLines` |
| 名前付き数式・ユーザー定義関数 | PascalCase | `UserFullName`、`FormatCurrency` |
| データソース・接続 | 追加時の名前を変更しない（数式・依存関係が壊れる） | `Accounts`、`Office365Users` |

- 既存アプリが別の命名で統一されている場合は**そちらを優先**する（部分適用による混在を避ける）
- 【絶対禁止】**`.pa.yaml` を直接編集してコントロール名・画面名を改名しない**。Studio 上での改名は参照する全数式が自動追随するが、YAML 直編集では追随せず、参照が壊れたまま気付けない。改名が必要な場合は「Studio で実施する手順」をユーザーに提示する

## 2. まず機械で直す（手作業より安全）

Power Fx には CLI の整形ツールが無い。以下を使う。

| 手段 | 内容 |
|---|---|
| Studio の数式バー「テキストの書式設定」 | 数式のインデント・改行を正規化する。**リファクタリング前にこれを実行**すると差分が読みやすくなる |
| App Checker（Studio 内） | 委任警告・アクセシビリティ・エラーを一覧化する。リファクタリング前後で警告件数を比較する |
| `pac canvas pack` / `unpack` | `.msapp` ⇔ ソース形式の変換。**バージョンによって対応状況・出力形式が変わる**ため、`pac help canvas` で現在の仕様を確認し、`unpack → pack → 再度 unpack` のラウンドトリップで差分が出ないことを検証してから編集に入る |

- `pac` の呼び出し方・格納パスは `/tool-environment` に従う（`%USERPROFILE%\.dotnet\tools\`）
- 作業対象は**アンマネージド環境のソリューション**に限る。マネージド環境・本番環境での編集は `.claude/rules/environment-safety.md`（【要指示】）に従う

## 3. 振る舞い保持の検証

| 手段 | 内容 |
|---|---|
| App Checker | エラー・委任警告が増えていないこと |
| Studio でのプレビュー実行 | 主要画面の表示・保存・検索の動作確認 |
| Power Apps Test Engine / Test Studio | 導入済みの場合のみ。プレビュー機能でありバージョン依存 |

自動テストが整備されていないことが多いため、**着手前に「何をどう確認したら振る舞い保持と見なすか」をユーザーと合意**する（`SKILL.md`「テストに関する注意」）。合意した確認項目は変更適用後に必ず実施し、結果を報告する。

## 4. Power Fx 固有のリファクタリング手法

| 症状 | 対応 | 根拠 |
|---|---|---|
| `If` の深いネスト | 単一値の分岐は `Switch`、条件式が異なるなら `If` の平坦化 | 可読性 |
| 同じ式を何度も再計算 | `With({ x: ... }, ...)` で中間値に名前を付ける | 可読性・重複排除 |
| 複数画面で重複する式 | `App.Formulas` の名前付き数式、またはユーザー定義関数へ抽出 | DRY |
| `OnVisible` に長い初期化処理 | 名前付き数式に移し、宣言的に評価させる（`Set` の削減） | 状態の削減 |
| `Set` で保持している「計算できる値」 | 名前付き数式に置換（常に最新になり、更新漏れが無くなる） | 派生状態の排除 |
| コントロールのプロパティに長い数式 | 名前付き数式へ抽出し、プロパティからは名前で参照 | 「関数 50 行」の代替 |
| 未使用のコントロール・画面・変数 | 削除（削除前に App Checker と全文検索で参照が無いことを確認） | デッドコード削除 |
| ハードコードされた色・サイズ | テーマ用の名前付き数式または定数コレクションに集約 | 保守性 |
| `ForAll` 内の `Patch` の多重ループ | 単一の `Patch`（レコード配列）に集約できる場合は集約する | 性能・可読性 |

## 5. 【禁止】振る舞いが変わるため実施しない変換

- 【絶対禁止】`.pa.yaml` の直接編集による**コントロール名・画面名の改名**（上記 1 節）
- **データソース名・接続名の変更**、および Dataverse スキーマ名の改名（`SKILL.md`「Power Platform 案件での注意」）
- **委任警告を消すための `Filter` / `Sort` 条件の書き換え**: 委任可能な形にすると**返る件数が変わる**（非委任時は先頭 500〜2000 件のみが対象だった）。これは不具合の修正であり、リファクタリングではない
- `Concurrent()` による並列化、`ForAll` の評価順序に依存した処理の並べ替え
- `.pa.yaml` のキー順・インデント・コントロール階層の並べ替え（Studio が再生成するため差分が壊れ、レビュー不能になる）
- `Collect` → `ClearCollect` の置換（既存データの扱いが変わる）
- 数式の `Blank()` / `""` / `0` の相互置換（`IsBlank` / `IsEmpty` の判定結果が変わる）
- エラーハンドリング（`IfError`・`Errors`）の削除・簡略化
- アプリ設定（`Formula-level error management` 等のプレビュー機能フラグ）の変更
