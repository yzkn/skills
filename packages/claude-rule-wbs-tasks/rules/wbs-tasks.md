# WBS・進捗管理資料の編集規約（パス条件付き適用）

`task/` 配下の WBS（`wbs.md` / `wbs.csv` / `wbs.xlsx`）・課題管理表を AI/人間が編集する際の必須ルール。
sprint-planner サブエージェントが WBS を生成する場合も本規約に従う。

## 1. データソースの一元化

- WBS タスクの追加・更新・削除は、すべて `task/` 配下の WBS 本体に対して行う
- 別ファイルにバックアップ・作業用コピーを作らない（履歴は git が担保する）
- CSV / Excel 形式を使う場合は BOM 付き UTF-8 で保存する（Excel での文字化け防止）

## 2. ID の採番規則

- ID は階層ドット記法（例: `1.1.2`。`n.0` はフェーズ行）で、WBS 内で一意とする
- 新規追加時は**既存の同階層 ID の最大値 + 1** を割り当てる
- 削除した ID は再利用しない（履歴の追跡性を保つ）

## 3. 依存関係の参照整合性

- 依存関係（先行タスク）には**存在する ID のみ**を記載する
- タスク削除の前に、他タスクから参照されていないかを必ず確認する
- 複数指定はセミコロン `;` 区切り（例: `1.1.1;1.1.2`）。要素の前後に空白を入れない
- 自己依存・循環依存を作らない

## 4. ステータス遷移と日付・進捗の連動

ステータスを変更したら、以下のカラムを**同時に**更新する（片方だけの更新は禁止）。

| 操作 | 必須の連動更新 |
|---|---|
| 状態を「進行中」に変更 | 実績開始日を当日で記入（既に値があればそのまま） |
| 状態を「完了」に変更 | 実績終了日を当日で記入 / 進捗を 100% にする |
| 状態を「保留」に変更 | 備考に保留理由を 1 行追記する |
| 進捗を更新 | 0〜100 の整数（%）。100% にする場合は状態も「完了」にする |

- 状態の値は `未着手` / `進行中` / `完了` / `保留` に統一する
- 日付は ISO 8601（`YYYY-MM-DD`）で統一する

## 5. フェーズ行（親）の扱い

- フェーズ行（`n.0`）には担当者・進捗・状態・日付を直接記入しない。子タスクから導出する
  - フェーズの期間: 子の最早開始日 〜 最遅終了日
  - フェーズの進捗: 子の見積工数を重みとした加重平均（工数未記入なら単純平均）
  - フェーズの状態: 全子完了→完了 / 1 つでも進行中→進行中 / それ以外→未着手
- フェーズ行が持ってよいのは ID・フェーズ名・備考のみ

## 6. マイルストーン

- マイルストーンは「特定日のイベント」であり、工数・進捗・担当者を持たない
- 持つのは ID・名称・予定日・実績日・状態（達成/未達成）・依存関係のみ

## 7. 編集後の整合性セルフチェック

WBS を編集したら、以下を確認してから完了報告する。

- [ ] 存在しない ID への依存参照がない
- [ ] 「完了」なのに実績終了日が空、「進行中」なのに実績開始日が空の行がない
- [ ] 進捗 100% と状態「完了」が一致している
- [ ] フェーズ行に直接値が記入されていない
- [ ] ID の重複・欠番の意図しない発生がない

不整合を検出した場合は修正案を提示し、ユーザーの確認を得てから修正する。

## 進捗管理資料の格納場所

WBS・課題管理表などは `./task/` に格納する。

| 資料種別 | 例 |
|---|---|
| WBS | `wbs.xlsx`、`wbs.md` |
| 課題管理表 | `issues.xlsx`、`issues.md` |
| スケジュール表 | `schedule.xlsx` |
| 議事録 | `minutes_YYYYMMDD.md` |
