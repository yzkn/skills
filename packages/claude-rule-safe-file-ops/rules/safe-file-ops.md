# ファイル操作の安全規則（常時適用）

- **削除は慎重に**: 不可逆的な操作はユーザーの明示的な指示を確認してから実行する
- **テキスト編集前のスコープ明示**: テキストファイルを編集する前に、変更対象の範囲（ファイル名・変更箇所・想定される増減バイト数/文字数）をユーザーに伝えてから作業を開始する
- **ファイル操作後の完全性確認**: 操作前後の行数を比較し、意図した範囲内に収まっていることを確認する。不一致はユーザーへ即報告する
- **形式変換はクロスツール検証**: Office / PDF を Markdown 等へ変換してファイルとして保存する場合、**変換に使ったツールとは別のツール**で同じ原本を再変換して突き合わせ、欠落・崩れを検出する（例: 変換 markitdown → 検証 pandoc）。同一ツールの再実行・オプション変更は検証にならない。形式ごとの検証ツール・照合指標は `.claude/skills/office/SKILL.md`「変換の検証（クロスツール検証）」に従い、差分があれば独断で採用せずユーザーに報告する
- **テキスト形式の相互変換は `/vnl text convert` に通す**: JSON / YAML / CSV / TSV / Markdown 表 / XML の相互変換を手で書き起こさない。変換結果は決定論的であり、手作業による行の取り違え・エスケープ漏れ・入れ子の潰れは「もっともらしい出力」に見えるため、読み手が検証なしに誤りを見分けられない。上の項目が Office / PDF をファイルとして保存する際の検証を扱うのに対し、本項目はテキスト形式そのものの変換を対象とする
- **編集後の diff 検証**: 編集完了後、変更量（追加・削除バイト数/文字数）が事前に伝えたスコープの範囲内に収まっていることを確認する。大きく乖離している場合はユーザーへ即報告する
- **編集前の必読**: ファイルを編集する前に必ず Read ツールで内容を確認する。未読ファイルへの Edit/Write は禁止
- **0バイト化の防止**: 編集後にファイルが 0 バイトになっていないことを確認する。検出した場合は即中断・ユーザーへ報告・内容を復元する
- **文字コード・改行コード・BOM を検査する**: テキストファイル（`.ps1` `.sh` `.py` `.json` `.md` `.yml` `.bat` 等）を**新規作成・編集・他所からコピーしたら**、`python .claude/scripts/check-encoding.py <パス...>` を実行する。ERROR があれば終了コード 1 を返し、`--fix` で BOM と改行コードを修正できる。**`.ps1` は UTF-8 BOM 必須**（無いと PowerShell 5.1 が cp932 として読み構文エラーになる）、**`.sh` は BOM 禁止かつ改行 LF 必須**（CRLF は Git Bash で実行できず、`bash -n` では検出できない）。文字コードは UTF-8 に統一する。種別ごとの要件・書き込み手段ごとの落とし穴・実測事例は [`../docs/text-encoding.md`](../docs/text-encoding.md)
- **スクリプトを実行する前にも検査する**: 自分が書いたものでなくても、`.ps1` / `.sh` を実行する前に `check-encoding.py` を通す。この種の不一致は書いた直後には現れず、実行して初めて壊れる
- **ユーザー自身が実施する操作の尊重**: 「私が行います」「自分でやります」等の返答を受けた場合、その操作を実行してはならない
