# /trouble-shoot スキル — トラブルシューティング支援

**引数:** $ARGUMENTS

「トラブルシューティングガイド」に基づき、ITシステム障害対応を8ステップで進行する。
`trouble-shooter` サブエージェントを起動して対話形式で調査を進める。

---

## 引数の解釈

| 引数の形式 | 動作 |
|---|---|
| `<問い合わせ内容>` | Step 1（一次回答）から新規セッションを開始する |
| `resume <セッションファイルパス>` | 指定した session.md から中断ステップを再開する |
| （なし） | 問い合わせ内容の入力を促してから新規セッションを開始する |

---

## 実行手順

### 引数が `resume <パス>` の場合

Agent ツールで `trouble-shooter` を起動し、指定したセッションファイルを渡す:

```
Agent({
  subagent_type: 'trouble-shooter',
  prompt: 'resume: <パス> のセッションを再開してください。セッションファイルを読み込み、中断したステップから対話を再開してください。'
})
```

### 引数に問い合わせ内容がある場合

Agent ツールで `trouble-shooter` を起動し、問い合わせ内容を渡す:

```
Agent({
  subagent_type: 'trouble-shooter',
  prompt: '新規トラブルシューティングを開始してください。問い合わせ内容: <引数の内容>'
})
```

### 引数がない場合

ユーザーに以下を確認してから起動する:

> 問い合わせ内容とシステム名を教えてください。
> または、既存のセッションを再開する場合はセッションファイルのパスを教えてください。

---

## 出力の確認

`trouble-shooter` サブエージェント完了後、以下をチャットに表示する:

- 生成されたセッションファイルのパス
- 現在のステップと次のアクション
- 障害報告書のパス（Step 8 完了時のみ）

---

## 注意事項

- 本スキルは `trouble-shooter` サブエージェントの起動窓口であり、調査ロジック本体はサブエージェント側にある
- セッションは `./report/trouble/<日時>_<件名>_session.md` に保存されるため、Claude Code を再起動しても `resume` で継続できる
- 詳細なポストモーテム・MTTD/MTTR 分析が必要な場合は、報告書完成後に `incident-responder` サブエージェントを使用する
