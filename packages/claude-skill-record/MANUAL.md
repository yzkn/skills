# /record — マニュアル

## 1. 前提

| 項目 | 内容 |
|---|---|
| 対象 | Claude Code（CLI / VS Code 拡張 / デスクトップアプリ） |
| 検証環境 | Windows 11 Pro / PowerShell 5.1 と 7.x / Python 3.14 / Git Bash |
| 文字コード | すべて UTF-8。`.ps1` は **BOM 必須**、`.sh` は **BOM 禁止・改行 LF** |
| 前提ツール | なし（Claude Code のみ） |

## 2. 収録物

| パス | サイズ | 役割 |
|---|---|---|
| `skills/record/SKILL.md` | 7.6 KB | スキル本体（frontmatter の `description` で自動適用される） |

## 3. 導入手順

```sh
# 導入先のプロジェクトルートで実行する
mkdir -p .claude/skills
cp -r skills/record .claude/skills/
```

**スキルは必ずディレクトリ形式（`.claude/skills/record/SKILL.md`）で置く。** フラットな `.md` として置くとスキル登録機構に載らず、自動適用も `/record` での呼び出しもできない。

### 3-1. 呼び出し方

- 自動適用: frontmatter の `description` に一致する依頼があったとき
- 明示呼び出し: `/record`

**自動適用は `description` だけでは安定しない。** 元リポジトリでの実測では、発動を左右するのは説明文の充実度より**常時適用ルールからスキル名を名指しすること**だった。確実に使いたい場合は、導入先の `CLAUDE.md` かルールから `/record` を名指しする。

## 4. 内容の構成

本体（`skills/record/SKILL.md`）の見出し構成:

- 引数の解釈
- 通常記録の実行手順（引数が "adr" で始まらない場合）
  - doc/prompt/ フォーマット
- ユーザープロンプト
- Claude Codeの応答
  - doc/thought/ フォーマット
- 問題・課題の認識
- 検討内容
- 結論・判断
- ADR 作成の実行手順（引数が "adr <タイトル>" の形式の場合）
  - ADR にするかの判断（粒度）— 本リポジトリの正本
  - doc/adr/ フォーマット
- コンテキスト
- 検討した選択肢

## 5. 導入後の検証

- `/record` で明示呼び出しできるか（できない場合はディレクトリ形式・frontmatter の `name` を確認する）
- 自動適用されるか（`description` に一致する依頼文で試す）

## 6. 既知の制約

- 本文が切り出し元のディレクトリ構成（`design/`・`report/`・`task/` 等）を前提にしている箇所がある
