# next — 次にやることを決める（再開・優先度の再判定・着手・手が空いたとき）

指令リポジトリの `AGENTS.md`「7. 着手の順」を、手順にしたもの。**どれか 1 つ**を選んで行う。

## いつ行うか

- 起動時（ログオン時）・スリープ解除時に、自動で起こされたとき（`kick.ps1`。最初の指示に `/auto-loop next` とある）
- `auto-resume-global` が再開したセッションで、担当中のタスクが無い・終わったとき
- タスクを終えた（`finish`）あと、続けて次に進むとき。「次にやることを決めて」と頼まれたとき

## 手順

1. **状況を取る。**

   ```
   pwsh -NoProfile -File <scripts>/status.ps1 -Json
   ```

   見るもの: `tasks`（状態ごとに、優先度の高い順・古い順に並んでいる）、`inbox` / `inboxUrgent`（受付の未整理と、そのうち `優先: 緊急`）、`idle`（手が空いた時に実行するタスクの定義。`due` が実施できるもの）、`active`（この PC で進行中の印）
2. **受付に未整理の件があれば、先に起票する**（[intake.md](intake.md) の A）。`優先: 緊急` は `-Priority urgent`
3. **優先度を判定しなおす。** 近傍のタスク（自分が担当中の `doing` / `waiting` / `blocked`、自分に合う `ready`）を見比べる。強い順に: `priority`（`urgent` > `high` > `normal` > `low`）→ 回答・承認が届いた `waiting`、原因が取り除かれた `blocked` → 期限・ほかのタスクの前提 → 古い順。**`urgent` に上げてよいのは利用者だけ**
4. **次の表で、行うことを 1 つ決める。**

   | 状況 | 行うこと |
   |---|---|
   | 自分が担当中のタスクがあり、緊急の `ready` が無い | **再開**（[resume.md](resume.md)）。担当中が複数なら、3 の順で 1 件 |
   | 自分が担当中のタスクがあるが、緊急の `ready` がある | **緊急への切り替え**（下の節） |
   | 自分が担当中のタスクが無い（または、どれも回答待ちで進められない）。自分に合う `ready` がある | **着手**（[start.md](start.md)。3 の順で 1 件。下の「1 台 1 リポジトリ」を先に確かめる） |
   | 着手できる通常のタスクが無い | **手が空いたときの作業**（下の節）。行えるものが無ければ、何もしない |

5. **選んだ理由を残す。** 着手・再開するタスクのログに 1 行（`claim.ps1 heartbeat <タスク ID> -Note 'next: <何を選んだか・なぜか>'`）。起票時と順が変わったときは、その理由も
6. 利用者に、何を選んだかを 1〜2 文で述べてから進める

## 緊急への切り替え

担当中のタスクは続けるのが原則。**`priority: urgent` のタスクだけは先に行う。**

1. いまのタスクを、区切りのよいところまで進める（中途半端な外部への公開操作を残さない）
2. いまのタスクの「現在地」に「緊急タスク `<ID>` のため中断」と次の一手を書き、[checkpoint](checkpoint.md) する。担当は保つ（`status` は `doing` のまま）。緊急タスクが長引く見込み（目安 24 時間超）なら、`claim.ps1 release <タスク ID> -Status ready` で解放する
3. 緊急タスクを [start](start.md) する
4. 終わったら、中断したタスクに [resume](resume.md) で戻る

緊急でも、承認の境界（`policy.md`）は変わらない。

## 1 台 1 リポジトリ

利用枠を使い切って全部が止まるのを防ぐため、**同じ PC では、同時には 1 つの作業対象リポジトリのタスクだけ**を進める。

- claim の前に、同じ PC のエージェント（`roster.md` の「PC」が同じ ID。自分を含む）が `doing` のタスクを持っていないか、1 の一覧で確かめる。別のリポジトリのタスクが進んでいれば、新しいタスクに着手しない
- 例外: 1 つのタスクが複数のリポジトリにまたがるもの / 緊急タスク（並行ではなく、中断してから）/ 利用者がその場で並行を指示したとき（「決定事項」に記録する）

## 手が空いたときの作業

自分に合う `ready` も、続けられる担当中のタスクも無いときに、**軽い作業を 1 件だけ**行う。

1. 選ぶ。1 の `idle` のうち `due` が `true` のものを、上から 1 件。定義が 1 件も無いときは、次のどれか 1 つ: `~/CLAUDE.md` などの設定ファイルの整理 / 既存のアプリケーション（`projects/` の案件）のリファクタリング / 仕様・機能の追加の提案 / ドキュメントの拡充
2. 起票する。案件に属さないもの（定義の案件が `設定`）は起票せず、結果を報告する

   ```
   pwsh -NoProfile -File <scripts>/new-task.ps1 -Project <案件> -Title <件名> -Slug <短い名前> -Stage <propose|implement> -Priority low -Source idle
   ```

   段階は、定義の `段階:` に従う（無ければ `propose`）。**マージはしない**
3. `inbox.md` のその定義の `最終実施:` を書き換える（`最終実施: <日付> <タスク ID か 1 行の結果>`）。定義そのものは消さない
4. [start](start.md) から普通に進める。ただし
   - 1 回に 1 件。終わっても、続けて次の作業を選ばない
   - サブエージェントへの委任・並列をしない
   - 範囲を小さく切る（目安: 提案 1 本、または PR / MR 1 本。定義に `範囲:` があればそれ）。広げたくなったら、提案として書いて止める
   - `~/CLAUDE.md`・`settings.json` などグローバルの設定の書き換えは、変更の案（差分）を作り、`status: waiting` で承認を待つ（`policy.md`）
   - 途中で通常のタスク（`ready`・回答の届いた `waiting`・受付の新しい件）が現れたら、区切りで checkpoint して、そちらを先に行う

## 人が見ていないとき（自動で起こされたとき）

- 承認が要る操作は行わず、タスクファイルの「承認が要る操作」「利用者への質問と回答」に書いて待つ（`status: waiting`）
- 区切りごとに checkpoint する。やることが無くなったら、何をしたかを 1〜2 文で述べて止まる（起こされたセッションは、記録がしばらく書かれなければ自動で終わる。続きは、次に起こされたセッションがタスクファイルを読んで行う）
