# checkpoint — 状態の記録

「いま会話が切れても、タスクファイルだけで続けられるか」を基準に書く。

## いつ行うか

- 計画のステップが 1 つ終わったとき
- 委任の**前**（誰に・何を・どの作業ツリーで）と**後**（結果）
- 外部への公開操作（push・PR / MR の作成・マージ）の前後
- 利用者の判断・承認を待つ状態に入るとき、決定をもらったとき
- 長い処理・大きな並列を始める前（上限で止まるかもしれない）
- しばらく記録していないとき（目安 1 時間）

## 手順

1. タスクファイルを直接編集する（自分が担当しているファイルだけ）

   | 節 | 書くこと |
   |---|---|
   | 計画 | 終わったステップに `[x]` と、成果物への参照。計画が変わったら直す（消さずに、変えた理由を 1 行） |
   | 現在地 | **進行中**（いま何の途中か）、**次の一手**（再開した者が最初にやること。コマンドやファイルの場所まで）、再開時に確かめ直す前提、作業ブランチ |
   | 決定事項 | 利用者の判断・承認を、日付つきで |
   | 利用者への質問と回答 | 判断が要ることを、選択肢と影響つきで書く（利用者がこのファイルに直接答えられる形で） |
   | 委任 | 名前・内容・モデル・ブランチ・作業ツリーの場所・状態（実行中 / 完了 / 停止 / 仕上げ済み） |
   | 成果物 | PR / MR の URL と状態 |
   | 未確認・推測 | 確かめられていないこと、推測のままの判断、前の報告の訂正 |
   | 実地確認の記録 | 実際に起きて確かめられたこと（いつ・何が・何で確かめたか） |

2. 印を付けて送る

   ```
   pwsh -NoProfile -File <scripts>/claim.ps1 heartbeat <タスク ID> -Note '<1 行の要約>'
   pwsh -NoProfile -File <scripts>/claim.ps1 heartbeat <タスク ID> -Status waiting -Note '<何を待っているか>'
   ```

   `-Status` は `doing`（既定のまま）/ `waiting`（利用者の判断・承認待ち）/ `blocked`（外部の要因）。待ちが解けたら `-Status doing` で戻す

3. 結果を確かめる
   - 終了コード 2「主張が失われている」→ **作業を止めて**利用者に報告する（ほかのエージェントが引き継いだ）
   - 終了コード 1 → 状態は手元に書けている。通信・認証を確かめ、次の機会に送り直す。競合（`conflict`）なら、利用者が同じファイルに書き込んでいる。差分を読み、**利用者の書き込みを残す形で**直して送り直す

## 遵守事項

- 状態に、認証情報・個人情報を書かない。長い出力は貼らず、要点と場所を書く
- 「未確認・推測」を空のままにしない（無ければ「なし」と書く）
- 利用者の回答・決定がファイルに書かれていないか、送る前の取り込みで届いた差分を読む
