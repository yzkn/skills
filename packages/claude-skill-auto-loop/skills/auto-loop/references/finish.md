# finish — 完了の報告・解放・片付け

## 手順

1. **完了条件と照らす。** タスクファイルの「目的と完了条件」「計画」を読み、残りが無いか確かめる。残りがあれば、完了にせず、残りを利用者に示す
2. **検証をまとめる。** `project.md` の「検証の方法」のうち、流したもの・結果・流せなかったものを整理する。成果物（PR / MR）の実際の状態（未マージ / マージ済み / 検査の結果）を、記録ではなく実物で確かめる
3. **未確認を書く。** 「未確認・推測」に、確かめられていないこと（実機・実時間・権限が要るもの）を書く。あとで実地に確かめられたら「実地確認の記録」に足せるように、何を見れば確かめられるか（ログの場所など）も書く
4. **落とし穴を残す。** この作業で踏んだもののうち、次にも起きそうなものを `projects/<案件>/project.md` の「落とし穴」に日付つきで足す（案件に限らないものは、利用者に「キットの手引きに足すか」を尋ねる）
5. **片付ける。**
   - 使い終えた作業ツリー・手元の作業ブランチ（取り込み済みを確かめてから。未コミットの変更があれば消さない）
   - 立ち上げたローカルのサーバー・バックグラウンドの処理
   - `~/.claude/auto-loop/work/<タスク ID>/`（残す価値のあるものは利用者に確かめる）
   - リモートのブランチの削除は、`stage: merge` でマージ済みの自分の作業ブランチだけ。それ以外は承認が要る
6. **報告する。** 指令リポジトリの `templates/report.md` の順で（結論 → 成果物 → 確かめたこと → 確かめられていないこと → 推測のままの点 → 利用者の判断が要ること → 訂正）。同じ中身をタスクファイルの「成果物」「未確認・推測」に書く
7. **解放する。**

   ```
   pwsh -NoProfile -File <scripts>/claim.ps1 release <タスク ID> -Status done -Note '<1 行の結果>'
   ```

   タスクファイルは `archive/` に移り、この PC の進行中の印が消える

## 完了にしない場合

| 状況 | すること |
|---|---|
| `propose` で提案を出し、判断を待つ | `heartbeat -Status waiting`（担当は保つ）。判断が来たら、同じタスクで続ける（必要なら `stage` を書き換える） |
| `implement` で PR / MR を出し、マージは利用者が行う | 完了条件が「PR / MR の作成まで」なら `done`。レビューの指摘に対応する約束なら `waiting` |
| 続けられない（権限・別の PC でないとできない、など） | 「現在地」に引き継ぎを書き、`release -Status ready`。理由をログに |
| 取りやめ（利用者の指示） | `release -Status dropped -Note '<理由>'` |
