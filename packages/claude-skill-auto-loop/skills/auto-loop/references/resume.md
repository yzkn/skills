# resume — 中断からの再開

上限・再起動・セッションの分岐（`--fork-session`）・PC の替わりのあとに行う。**会話の記憶ではなく、タスクファイルを正とする。**

## 手順

1. **担当しているタスクを特定する。**

   ```
   pwsh -NoProfile -File <scripts>/status.ps1 -Mine
   ```

   - 「この PC で進行中の印」のうち、`cwd` がいまの作業フォルダに合うものが、このセッションの続き
   - 自分が担当のタスクが複数あって決まらないときは、利用者に確かめる
   - 印はあるのに一覧で `mine` でない → 担当を失っている。続けずに利用者に伝える
   - 1 件も無い → auto-loop の管理下の作業ではない。その旨を伝え、普通に続ける
2. **読む。** タスクファイル全体（とくに「現在地」「決定事項」「利用者への質問と回答」「委任」）と `project.md`。中断の間に利用者が書き込んだ回答・決定が無いか確かめる
3. **担当を保つ。** `pwsh -NoProfile -File <scripts>/claim.ps1 claim <タスク ID>`（自分の担当なら継続になる）。終了コード 2 なら続けない
4. **前提を確かめ直す。** 中断の前に動いていたものは、落ちている前提で確かめる
   - `preflight.ps1 -Project <案件>`（認証は数時間で切れることがある）
   - 「現在地」の「再開時に確かめ直す前提」（ローカルのサーバー・バックグラウンドの処理・ブラウザなど）
   - 補助ファイルは `~/.claude/auto-loop/work/<タスク ID>/` を見る。前のセッションの scratchpad は当てにしない
   - 作業ブランチの実物: `git status`・`git log`・PR / MR の状態が、タスクファイルの記録と合っているか。**食い違ったら実物を正とし**、タスクファイルを直す
5. **止まった委任を片付ける。**（下の節）
6. **再開を記録する。** `claim.ps1 heartbeat <タスク ID> -Note '再開: <何で中断していたか>。<次の一手> から続ける'`
7. 利用者に、中断時点で何をしていたか・これから何をするかを 1〜2 文で述べてから、「次の一手」から続ける

## 止まった委任

セッションが分岐すると、元のセッションのサブエージェントには続きを頼めないことがある（記録が元のセッションに属する）。

1. タスクファイルの「委任」の表で、状態が「実行中」のものを挙げる
2. それぞれについて、まず元のエージェントに続きを頼めるか試す（`SendMessage`）。頼めればそのまま続けさせる
3. 頼めなければ、作業ツリーの実物を見る: `git -C <作業ツリー> status` と `git log <起点>..HEAD`
   - 変更が無い・コミットも無い → 委任をやり直す
   - 変更が残っている → **新しいエージェントに、同じ作業ツリーで「仕上げ」を任せる**（[delegate.md](delegate.md) の「仕上げ」。済んだ部分をやり直させない）
   - 完了していた（報告だけが届かなかった）→ 親が検証して取り込む
4. 表の状態を更新する（停止 → 仕上げ中 → 完了）
5. 上限で止まった直後は、枠が戻りきっていないことがある。並列の数を控える

## 別の PC・別のエージェントが続けるとき

元の担当が解放（`release -Status ready`）していれば、普通に `start` する。解放されていない担当を引き継ぐ（`claim.ps1 takeover`）のは、**利用者の指示があるときだけ**。引き継いだら、作業ブランチを取得し（元の PC の未 push の変更は届かない）、手元に無いものを「未確認・推測」に書く。
