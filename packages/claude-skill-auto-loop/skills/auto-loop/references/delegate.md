# delegate — サブエージェントへの委任

定型の繰り返し・範囲のはっきりした実装・文書への反映を、サブエージェント（軽いモデルなど）に任せる。調査・設計・横断的な判断・統合・報告は親が行う。

## 委任の前に

1. **利用枠を確かめる。** 並列のサブエージェントは、同じアカウントの枠を一気に使う。上限が近いとき・残りが分からないときは、利用者に確かめるか、並列をやめて 1 本ずつにする。並列の数は `config.json` の `maxParallel`（既定 3）まで
2. **作業の場所を分ける。** 並列にするときは、委任ごとに作業ツリーとブランチを分ける（Claude Code なら `isolation: worktree`、または `git worktree add`）。ブランチの名前は `project.md` の「進め方」に従う
3. **渡すものが実在することを確かめる。** 指示書で「読め」と書くファイルは、親が存在を確かめてから渡す（書いたつもりで書けていないことがある）。セッションをまたぐ補助ファイルは `~/.claude/auto-loop/work/<タスク ID>/` に置く
4. **指示書を書く。** 指令リポジトリの `templates/delegation.md` の形で。受け手は会話の文脈を知らない。前提・やること・やらないこと・検証・終え方（報告の形）を、それだけで作業できるように書く
5. **記録してから起動する。** タスクファイルの「委任」の表に、名前・内容・モデル・ブランチ・作業ツリー・状態（実行中）を書き、`checkpoint` する。**起動の前に**記録する（起動の直後に上限で止まっても、次の者が作業ツリーを見つけられるように）

## 指示書に必ず入れる禁止事項

- 作業ツリーの外を編集しない
- push・PR / MR の作成・マージ・タスクの登録・ツールの導入をしない（親が、利用者の承認のあとに行う。サブエージェントが行うと権限の確認で止まる）
- 指令リポジトリを書き換えない（親が記録する）
- 前提と違う点・判断に迷う点は、進めずに報告に書く
- 区切りごとにコミットする（途中で止まっても続けられるように）

## 結果を受け取ったら

1. 報告をうのみにしない。差分（`git diff <起点>..<ブランチ>`）を読み、指示書の検証を親がもう一度流す
2. 親が統合する（作業ブランチへの取り込み、PR / MR ごとの整理）
3. 「委任」の表を更新し（完了）、`checkpoint` する
4. 使い終えた作業ツリーとブランチは、取り込みを確かめてから片付ける（`git worktree remove`。未コミットの変更が残っていたら消さずに確かめる）

## 仕上げ（止まった委任の引き継ぎ）

上限・再起動・分岐で止まり、元のエージェントに続きを頼めないときは、新しいエージェントに**同じ作業ツリー**で仕上げさせる。指示書に `templates/delegation.md` の「引き継ぎ」の節を足す。

- 親が先に `git status` と `git log <起点>..HEAD` を見て、コミット済みの範囲と未コミットの要約を指示書に書く
- 元の指示を再掲し、「済んだ部分をやり直さない。最初に、何が済み・何が残っているかを報告の冒頭に書く」と指定する

## モデルの使い分け

| 向いている作業 | モデル |
|---|---|
| 調査・設計・横断的な判断・統合・報告 | 上位のモデル（親） |
| 定型の繰り返し・範囲のはっきりした実装・PR の説明文・文書への反映 | 軽いモデル（サブエージェント） |

モデルごとに利用枠が別のことがある。上位のモデルの枠が尽きたら、利用者に伝えたうえで、軽いモデルで進められるステップ（定型の実装・文書）を先に進め、判断の要るステップは `waiting` で残す。
