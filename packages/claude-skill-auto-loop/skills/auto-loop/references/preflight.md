# preflight — 着手前の確認

認証切れ・push 先の削除予定・本流の取り違えを、作業の**最後ではなく最初**に見つける。着手のとき、再開のとき、外部への公開操作（push・PR / MR の作成）の直前に行う。

## 手順

1. 実行する（何も変更しない。`git fetch` だけ行う）

   ```
   pwsh -NoProfile -File <scripts>/preflight.ps1 -Project <案件>
   ```

2. 結果を読む。1 行 1 項目で `OK / INFO / WARN / NG`、`→` の行は直し方

   | 項目 | 確かめていること |
   |---|---|
   | 設定・道具 | この PC の設定、git |
   | 指令リポジトリ | 取得と push ができるか、未コミットの変更 |
   | 認証 `<ホスト>` | `gh` / `glab` のトークンが有効か、有効なアカウントが `project.md` の指定と合うか |
   | push 先 | リポジトリの権限、アーカイブ、**削除予定**（GitLab） |
   | 作業コピー | 本流のリモートが指定のリポジトリを指しているか、取得できるか、ローカルの基準ブランチの遅れ、未コミットの変更、**作業ツリーに残った変更**（止まった委任の置き土産） |
   | 自動再開・利用枠 | `auto-resume-global` との連携、並列の前の注意 |

3. **NG を先に片付ける。**
   - 認証切れ・アカウント違い: 示されたコマンドを利用者に頼む。`!` で実行するコマンドは非対話なので、**完全な形**（`! gh auth login --hostname github.com --web` など）で示す。アカウントの切り替え（`gh auth switch`）は、利用者に確かめてから行う
   - push 先が削除予定・アーカイブ済み: 本流が別の場所に移っていないか、利用者に確かめる。`project.md` を直す
   - 直せない NG は、タスクを `status: blocked` にして理由を書く（`claim.ps1 heartbeat <ID> -Status blocked -Note '<理由>'`）
4. **WARN を判断する。**
   - ローカルの基準ブランチの遅れ → 作業ブランチを `<本流リモート>/<基準ブランチ>` から切る（ローカルの基準ブランチを勝手に動かさない）
   - 未コミットの変更 → 誰の変更か確かめる。利用者のものなら触らない
   - 作業ツリーに残った変更 → タスクファイルの「委任」の表と照らす。続きなら [resume.md](resume.md) の「止まった委任」へ
   - clone の場所が未登録 → 利用者に確かめて `config.json` の `repoPaths` に足す
5. **スクリプトが見ないものを確かめる。**
   - 案件の `project.md`「検証の方法」に要る道具・ローカルのサーバー・ブラウザなどが使えるか（再開のたびに落ちている前提で確かめる）
   - これから行う操作のうち、権限の確認で止められそうなもの（push・PR / MR の作成・タスクの登録）を洗い出し、親のセッションで行う計画にする
   - 大きな並列の委任を始める前に、利用枠の残り（`/usage`）を利用者に確かめる。上限が近いなら並列を始めない
6. 結果の要点（NG・WARN と、その扱い）を、タスクファイルのログに 1 行残す
