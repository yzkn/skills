# 報告（ひな形）

区切りと完了のときに、この順で利用者に報告する。タスクファイルの「成果物」「未確認・推測」と同じ中身にする。

```markdown
## 結論
<1〜3 文。何ができて、何が残っているか>

## 成果物
- <PR / MR の URL — 内容 — 状態（未マージ / マージ済み）>

## 確かめたこと
- <何を・どうやって（コマンド・手順）・結果>

## 確かめられていないこと
- <実機・実時間・権限が要るものなど。なぜ確かめられないか、どうすれば確かめられるか>

## 推測のままの点
- <推測であることを明示する。根拠にした代表例>

## 利用者の判断が要ること
- <選択肢と、それぞれの影響。おすすめがあれば理由つきで>

## 訂正
- <前の報告・提案に誤りがあれば、何が誤りで、正しくは何か>
```

- 件数だけで判断しない。提案の根拠は、代表例を実際に読んで確かめてから書く
- 「何もしなかった」ことも、理由と一緒に書く
- 該当が無い節は「なし」と書く（節ごと消さない）
