# 受付

新しい依頼を、この下（「手が空いた時に実行するタスク」の節より上）か、末尾の目印の下に足してください。どちらに書いても、エージェントが次の機会にタスクファイルへ起こし、ここからは消します。

書き方（見出しの 1 行だけが必須。あとは自由）:

```markdown
## <案件>: <件名>
段階: 提案だけ | 実装まで | マージまで      ← 省くと「提案だけ」
担当: any | claude | <エージェントの ID>     ← 省くと any
優先: 緊急 | 高 | 普通 | 低                   ← 省くと普通

（やってほしいこと・完了の条件・やらないこと・参考の場所を自由に）
```

- 案件は `projects/` のフォルダ名。新しい案件なら `## 新規: <件名>` と書き、リポジトリの場所を本文に書く
- 進行中のタスクへの追加の指示は、ここではなく、そのタスクファイルの「決定事項」に書く
- `優先: 緊急` と書いた依頼は、エージェントが作業中のタスクを中断して先に行う（`priority: urgent`）。それ以外は、着手のたびに優先度を見比べて高いものから行う（[AGENTS.md](AGENTS.md) の「7. 着手の順」）

## 手が空いた時に実行するタスク

着手できる通常のタスクが無いとき、エージェントがここから**上から順に 1 件だけ**選んで行います（[AGENTS.md](AGENTS.md) の 7.5）。ここの定義は、行っても消しません（繰り返し使う）。見出しは `###` で書きます（`##` は通常の依頼として数えられる）。

書き方:

```markdown
### <案件>: <件名>
段階: 提案だけ | 実装まで                    ← 省くと「提案だけ」。マージはしない
間隔: 毎回 | 週 1 回 | 月 1 回 など           ← 省くと週 1 回。この内に実施済みなら飛ばす
最終実施:                                     ← エージェントが書く（日付と、タスク ID か結果）
範囲: （1 回に行う量の上限）

（やってほしいこと・やらないこと）
```

- 案件は `projects/` のフォルダ名。案件に属さないもの（PC の設定など）は `設定` と書く（タスクファイルは作らず、結果だけを報告する）
- 止めたい定義は、消すか、見出しを `### （停止）...` にする

<!-- 以下は指示の例（止めてある）。使うときは、案件名を自分のものに直し、見出しの「（停止）」を外す -->

### （停止）設定: ~/.claude/CLAUDE.md と設定ファイルの整理
段階: 提案だけ
間隔: 月 1 回
範囲: 1 回に 1 ファイル
最終実施:

`~/.claude/CLAUDE.md`（と、そこから読み込む `~/.claude/RTK.md` など）・各リポジトリの `CLAUDE.md` / `AGENTS.md` を読み、重複・古くなった記述・食い違いを挙げて、直す案（差分）を示す。書き換えは承認を得てから。認証情報が書かれていたら、内容を写さずに場所だけを報告する。

### （停止）my-app: 小さなリファクタリング
段階: 実装まで
間隔: 週 1 回
範囲: 1 回に PR / MR 1 本（1 つのモジュール・変更 200 行まで）
最終実施:

重複したコード・使われていない関数・長すぎる関数を 1 か所だけ選んで直す。挙動は変えない。既存のテストが通ることを確かめる。公開の API・ファイルの配置は変えない（変えたいときは提案として書く）。

### （停止）my-app: 仕様・機能の追加の提案
段階: 提案だけ
間隔: 月 1 回
範囲: 1 回に提案 3 件まで
最終実施:

使い勝手の改善・足りない機能を、根拠（該当の画面・コードの場所）を添えて提案する。実装はしない。過去の提案（`archive/`）と重ならないものにする。

### （停止）my-app: ドキュメントの拡充
段階: 実装まで
間隔: 月 1 回
範囲: 1 回に PR / MR 1 本（1 つの文書）
最終実施:

README・手順書で、実際の動きと食い違っている箇所・説明が足りない箇所を 1 つ選んで直す。確かめていない動作を書かない。
