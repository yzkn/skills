# /release-guide スキル — バージョニングとリリース手順

アプリケーションのバージョン管理とリリース作業の規約を定義する。

## 適用方法

`/release-guide` で直接呼び出せるほか、バージョン番号の決定・タグ付け・リリース作業時に Claude Code が自動参照し、「リリース手順を確認して」のような依頼でも適用される。

---

## セマンティックバージョニング

アプリケーションのバージョン管理には **[Semantic Versioning 2.0.0](https://semver.org/lang/ja/)** を使用する。

<!-- profile:standard-only 以下は SemVer 仕様そのものの要約（一般知識） -->

バージョン番号は `MAJOR.MINOR.PATCH` の形式で表す。

| 番号 | 上げるタイミング | 例 |
|---|---|---|
| MAJOR | 後方互換性のない破壊的変更 | API の仕様変更、データ構造の非互換変更 |
| MINOR | 後方互換性を保った機能追加 | 新機能の追加、既存機能の拡張 |
| PATCH | 後方互換性を保ったバグ修正 | 不具合修正、軽微な改善 |

<!-- /profile:standard-only -->

---

## バージョン管理のルール

- バージョンは git タグで管理する（例: `v1.2.3`）
- リリース時はタグ付けをユーザーに確認してから実施する
- 開発中の未リリースバージョンは `-alpha`・`-beta`・`-rc.1` 等のプレリリース識別子を付与してよい

---

## リリース前チェックリスト

- [ ] 変更内容が `MAJOR`・`MINOR`・`PATCH` のどれに該当するか確認する
- [ ] CHANGELOG またはリリースノートを更新する
- [ ] ステージング環境でのスモークテストが完了している
- [ ] 本番デプロイの承認を得ている（`/deploy-guide` 参照）
- [ ] git タグを作成してリモートにプッシュする
