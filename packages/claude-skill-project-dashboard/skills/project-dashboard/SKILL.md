# /project-dashboard スキル — プロジェクト状況ダッシュボード生成

**引数（オプション。`--artifact` で Artifact 公開も行う）:** $ARGUMENTS

`task/`・`design/`・`doc/adr/`・`report/` の現在状態を集約し、単一の自己完結 HTML ダッシュボードとして `report/dashboard/index.html` に生成する。

## 位置づけ

- **ダッシュボードは派生物**である。正本は `task/`・`design/` 等の各ファイルであり、ダッシュボードは何度でも再生成する。手編集しない
- `report/dashboard/index.html` への上書きは正常動作（証跡ではないため不変性ルールの対象外）
- 情報の収集のみを行い、**このスキルは正本を一切変更しない**

## 実行手順

### Step 1: データ収集

以下を読み取り、存在しないものは「データなし」として扱う（エラーにしない）。

| ソース | 収集内容 |
|---|---|
| ルート `CLAUDE.md` §0（存在する場合） | プロジェクト名・概要・現在フェーズ |
| `task/wbs.md`（または `task/*.xlsx` を office スキルで読取） | タスク一覧・ステータス・予定日・遅延（終了予定日 < 今日 かつ 未完了） |
| `task/issues.md` | 課題一覧・優先度・オープン/クローズ |
| `doc/adr/*.md` | 直近の意思決定（新しい順に最大 5 件、タイトルと日付） |
| `design/**/*.md` | フェーズ別ファイル数・最終更新日・`==〜==`（未確定マーク）の残存数 |
| `intake/extract/extract_*.md` | 直近の受領資料・議事録（新しい順に最大 5 件） |
| `report/*/` | 直近の診断レポート（新しい順に最大 5 件、種別付き） |
| `git log --oneline -10` | 直近のコミット概要 |

### Step 2: 指標の算出

- **フェーズ進捗**: `design/01_planning/`〜`08_operations/` の成果物有無と WBS のフェーズ別タスク完了率から、各フェーズを 未着手 / 進行中 / 完了 に分類
- **タスク内訳**: ステータス別件数（未着手・進行中・完了・保留）と遅延件数
- **課題内訳**: 優先度（高/中/低）× オープン件数
- **未確定事項**: 設計書内の `==〜==` 残存数（ファイル別）
- 判断に迷う値は推測で埋めず「要確認」と表示する

### Step 3: HTML 生成

`report/dashboard/index.html` に単一ファイルで出力する。

**必須要件:**

- **自己完結**: 外部 CDN・外部フォント・外部画像を参照しない（CSS/JS はインライン）
- **日本語 UI**・レスポンシブ（モバイルでも閲覧可能）
- ライト/ダーク両対応（`prefers-color-scheme`）
- 冒頭に生成日時と「本ファイルは自動生成の派生物。正本は task/・design/ 配下」の注記を明記

**推奨セクション構成:**

1. ヘッダー: プロジェクト名・現在フェーズ・生成日時
2. サマリーカード行: タスク完了率 / オープン課題数（うち高優先度） / 遅延タスク数 / 未確定事項数
3. フェーズ進捗（01_planning → 08_operations の横断ビュー）
4. 遅延・要注意タスク一覧（WBS ID・期限・担当）
5. オープン課題（優先度順）
6. 直近の意思決定（ADR）・受領資料・診断レポートへの相対リンク
7. 直近のコミット

グラフ描画が必要な場合はライブラリを使わず、インライン SVG または CSS バーで表現する（自己完結性の維持）。

### Step 4: 報告

- 生成先パスと、ダッシュボードから読み取れる**要注意事項**（遅延・高優先度課題・未確定の滞留）を 3 点以内でチャットに要約する
- 引数に `--artifact` がある場合、または共有を依頼された場合のみ Artifact として公開する（顧客名等の機微情報が含まれる場合は公開前にユーザーへ確認する）
