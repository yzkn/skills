# Git 安全規則（常時適用）

## 禁止事項

レベルの定義（【絶対禁止】/【要指示】）と、絶対禁止を指示された場合の標準応答は `.claude/rules/prohibition-levels.md` を参照。

- 【要指示】コミットはユーザーから明示的に指示された場合のみ実行する。指示なしのコミットは禁止
  - **例外1**: Stop フック（`.claude/hooks/auto-record.ps1`）による `./doc/prompt/` 配下の自動記録コミット
  - **例外2**: 診断エージェント（`owasp-check`・`riss-ioqeo` 等）がエージェント定義に明記された手順に従って行う `./report/` 配下の診断レポートのコミット
  - 例外はいずれも対象ディレクトリ配下のファイルのみをステージングすること。それ以外のファイルを含むコミットは禁止
  - **ステージングを絞るだけでは足りない。`git commit` に対象ファイルのパス指定を付ける**（例: `git commit -m "<msg>" -- ./report/owasp/<ファイル名>`）。パス指定を省略するとインデックス全体がコミットされ、実行前にステージされていた無関係な変更を巻き込む（実際に発生した事故と対処は ADR-023）
- 【絶対禁止】`git push` はユーザーのみが実施する。**ユーザーから指示・承認された場合を含め**、いかなる時も Claude Code が自ら実行してはならない。push が必要な場面では、実行すべきコマンド（例: `git push origin main`）を提示してユーザー自身の実行を依頼する
- 【要指示】フックのスキップ（`--no-verify`）はユーザーの明示的な指示がある場合のみ許可する
- 【絶対禁止】`main` / `master` への `push --force` は指示の有無にかかわらず絶対に実行しない（ユーザーへの提案も行わない）

## コミット前の機密情報チェック（必須）

コミット前に以下のパターンで機密情報を確認する。発見した場合はコミットを中断してユーザーに報告する。

```sh
git diff --cached
grep -rEi "(password|passwd|secret|api.?key|token|client.?secret|bearer|private.?key|AKIA[0-9A-Z]{16})" <対象ファイル>
```

チェック対象: 認証情報・APIキー・トークン・接続文字列・秘密鍵・PII・クラウド認証情報・クレジットカード番号・携帯電話番号

**画像・PDF**: スクリーンショット・モックアップに実際のメールアドレス・電話番号・氏名が映り込んでいないか Read ツールで視覚確認する。

## コミット後の証跡の取りこぼし確認（必須）

**作業ファイルをコミットしたら、同じターンで `git status --short doc/prompt/` を確認する。** ステージされたまま残っている自動記録があれば取りこぼしであり、放置してはならない。

- **Stop フック（`.claude/hooks/auto-record.ps1`）の自動コミットは fail-open である。** 失敗しても警告を `doc/log/error/auto-record-trace.log` に残すだけでセッションは正常に続くため、**「自動コミットされているはず」を前提にしない**
- 原因の第 1 候補は pre-commit フック（gitleaks）による拒否である。trace ログ末尾の `RuleID` を見て、誤検知なら `.gitleaks.toml` の既定方針（**値限定・ルール限定**の `[[allowlists]]`。パス単位の除外は採らない。`doc/adr/20260820_025_gitleaks誤検知の除外方針.md`）に従って除外側で対応する
- 【絶対禁止】**証跡（`doc/prompt/`・`doc/thought/`・`doc/adr/`）の内容を書き換えて検査を通す対処を採ってはならない**（証跡の不変性。`.claude/CLAUDE.md`）
- **予防（最も効く）: 12〜16 桁の数値を応答・コマンド・ファイルに書くときは、桁をそのまま連続させない。** **一度その文字列が証跡へ記録されると後から取り消せない**（証跡は編集禁止のため、以後は除外側でしか対応できない）。**検証用のダミー値も同様**（実際にダミー値が証跡のコミットを塞いだ。ADR-034）
  - 【必須】**ダミー値を作る前に `.gitleaks.toml` を読む。** 同ファイルの `[[allowlists]]` は **除外済み＝安全に使えるダミー値の登録簿**である。番号・カード番号・識別子のダミーが必要なときは**まず登録済みの値を再利用し**、新しい値を作るのは登録済みで用が足りないときだけにする
  - 新しいダミー値がルールに一致する形しか採れない場合は、**その値を応答・コマンド・ファイルへ書く前に**除外を追加してよいかユーザーに確認する。**証跡に記録されてからでは、除外の追加か `--no-verify` しか手が残らない**
  - **電話番号も対象である**（`mobile-phone-number` / `fixed-phone-number`）。`/vnl testdata` が生成する局番 `0000` の形式も現状のルールに一致するため、生成物をコミットする前に所見を確認する
  - 個人番号（12 桁）・法人番号（13 桁）のルールは連続数字だけに一致するので、**区切り記号を入れれば回避できる**（例: `978-0-306-40615-7`）
  - **クレジットカード番号のルールは区切り記号を許容するため、区切りでは回避できない。** 桁の一部を伏せる（例: `4242-42xx-xxxx-4242`）
  - 検出ルールそのものを検証する場合は、ルールに一致する値をコマンドや応答へ literal で書かず、**実行時に文字列連結・算術で組み立てて**一致する文字列を会話に残さない
- **作業ファイルがコミット済みで証跡だけが未コミットの状態を、ターンをまたいで残さない。** 自力で解消できない場合は、事象・原因・選択肢をその場でユーザーに報告する（過去に 7 日間気づかれず放置された。経緯は ADR-034）
