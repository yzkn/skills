# サードパーティライセンス規約（常時適用）

外部のライブラリ・パッケージ・ソースコード（コピー流用・スニペット含む）・ツール・フォント・アイコン・画像等のアセットをこのリポジトリに持ち込む際に適用する。レベルの定義（【絶対禁止】/【要指示】）は `.claude/rules/prohibition-levels.md` を参照。

ライセンス分類の一覧（permissive / コピーレフト / 商用制限付きの代表例と制約）は [`../docs/third-party-licenses-details.md`](../docs/third-party-licenses-details.md) に分離してある。**どの分類に当たるか判断がつかないときは Read する**（判断基準そのものは以下に残してある）。

## 持ち込み前の確認（必須）

- **ライセンス種別を必ず確認してから持ち込む**。確認していないもの・ライセンスが不明なもの・ライセンス表記が見当たらないものは持ち込まない
  - ライセンス表記のないコードは「全権利留保（利用許諾なし）」とみなす。パブリックドメインと推定しない
  - 確認元は一次情報（配布元の `LICENSE`・パッケージメタデータの `license` フィールド・公式ドキュメント）とし、推移的に引き込む二次依存も対象とする
- **実在性・供給元を確認する（ハルシネーションパッケージ対策）**: AI（Claude Code 自身を含む）が提案したパッケージ名は、実在しない名前を攻撃者が先回り登録する slopsquatting の標的になり得る
  - 公式レジストリ（npm / PyPI / NuGet 等）で実在を確認し、タイポスクワッティング（有名パッケージの類似名）でないかも確認する
  - 最終更新日・ダウンロード数・リポジトリの活動状況を確認し、放置されたパッケージや公開直後の無名パッケージは採用前にユーザーへ報告する
  - `package-lock.json`・`poetry.lock` 等の差分をコミット前にレビューし、意図しないパッケージが混入していないか確認する

## 持ち込み可否

- **原則として持ち込んでよいのは、商用利用可能でコピーレフト（ソースコード開示義務）のない permissive ライセンスのみ**（MIT・BSD・Apache 2.0・ISC・0BSD・Unlicense・CC0）。Apache 2.0・BSD 等が求める帰属表示・ライセンス全文・`NOTICE` の同梱義務は必ず遵守する
- 【要指示】**コピーレフト（GPL / AGPL / SSPL / LGPL / MPL 2.0 / EPL / CDDL）・商用制限付き（BUSL・Commons Clause）・プロプライエタリ / ライセンス不明のものは、Claude Code の判断で持ち込んではならない**。技術的に必要な場合は、トレードオフ（開示義務・派生物の扱い・商用上の制約）を提示してユーザーの明示的な指示を得たうえで、`/record adr` で採否の根拠を `./doc/adr/` に記録する
- 判断に迷うライセンス・デュアルライセンス・条件付きの例外は独断で解釈せず、ユーザーに確認する

## 作図アイコン・ロゴ

成果物に貼るアイコン・ロゴにも本ルールが適用される。**ライセンスが permissive（MIT・Apache-2.0・CC BY 4.0 等）であると確認できたものだけを使う。** コピーレフト（AGPL・CC BY-SA 等）・ライセンス表記のないものは、上記の【要指示】と同様にユーザーの明示的な指示を得る。

- **帰属表示の義務があるもの**（Apache-2.0・CC BY 4.0 等）は、資料末尾に表記を載せる。**ブランドロゴは商標**であり、permissive でも識別目的を超える使い方（自社サービスと誤認させる配置）はしない

## 記録と監査

- 採用したサードパーティのライセンスは、依存定義ファイル（`package.json`・`requirements.txt`・`*.csproj` 等）または設計書で追跡可能にする
- ライセンスリスク・既知 CVE・EOL の継続的な監査は `dependency-auditor` サブエージェント（SCA）を使用する
