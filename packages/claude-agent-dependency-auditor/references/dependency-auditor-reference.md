# dependency-auditor リファレンス — 診断コマンド・診断観点・レポートフォーマット

dependency-auditor エージェントから参照されるリファレンス。エージェント定義本体は `.claude/agents/dependency-auditor.md`。

## エコシステム別の自動診断コマンド（Step 3）

#### Node.js

```bash
# npm audit（JSON形式で出力）
npm audit --json 2>/dev/null | head -200

# 古いパッケージの確認
npm outdated 2>/dev/null | head -50
```

#### Python

```bash
# pip-audit（インストール済みの場合）
pip-audit --format=json 2>/dev/null | head -200

# pip list --outdated
pip list --outdated 2>/dev/null | head -50
```

#### .NET

```bash
# dotnet list package --vulnerable
dotnet list package --vulnerable 2>/dev/null | head -100

# dotnet list package --outdated
dotnet list package --outdated 2>/dev/null | head -100
```

#### Go

```bash
# go list -m all（依存関係一覧）
go list -m all 2>/dev/null | head -100
```

## 静的解析の診断観点（Step 4: 4-1〜4-4）

#### 4-1: バージョン固定の確認

| チェック観点 | 問題パターン |
|---|---|
| バージョン未固定 | `"*"`・`"latest"`・`">=x.x"`（範囲指定のみ） |
| フローティングバージョン | `"^x.x.x"`・`"~x.x.x"`（マイナー・パッチの自動更新） |
| ロックファイル不整合 | `package.json` と `package-lock.json` のバージョンが異なる |

#### 4-2: 既知 CVE の確認

ツールの自動診断で CVE が検出された場合は以下を記録する。

| 記録項目 | 内容 |
|---|---|
| パッケージ名・バージョン | 影響を受けるバージョン範囲 |
| CVE ID | `CVE-YYYY-XXXXX` 形式 |
| CVSS v3.1 スコア | ベーススコア（0.0-10.0） |
| 影響 | 機密性・完全性・可用性への影響 |
| 修正バージョン | アップグレード先のバージョン |

ツール自動診断が実行できなかった場合は WebSearch で主要パッケージの既知 CVE を調査する。
調査は重要度の高いパッケージ（認証・暗号化・Webフレームワーク等）を優先する。

#### 4-3: EOL（サポート終了）パッケージの確認

以下のパターンを Read・Grep で確認し、WebSearch で EOL 情報を補完する。

- メジャーバージョンが複数世代古いパッケージ
- 公式サポートが終了したランタイムバージョン（`Node.js`・`Python`・`.NET`等）

**主要ランタイムの EOL 参照先**（WebSearch で最新情報を確認すること）

| ランタイム | 参照先 |
|---|---|
| Node.js | nodejs.org/en/about/previous-releases |
| Python | devguide.python.org/versions |
| .NET | dotnet.microsoft.com/en-us/platform/support/policy |
| Java (OpenJDK) | endoflife.date/java |

#### 4-4: ライセンスリスクの確認

依存関係ファイルから主要パッケージのライセンスを確認し、リスクを評価する。

| ライセンス種別 | リスクレベル | 内容 |
|---|---|---|
| MIT・BSD・Apache 2.0 | 低 | 商用利用可能・コピーレフト条項なし |
| LGPL | 中 | リンク方式によっては制約あり |
| GPL v2 / v3 | 高 | 成果物のオープンソース化義務が生じる可能性 |
| AGPL | 高 | ネットワーク越しの提供にもオープンソース化義務 |
| 商用ライセンス | 要確認 | 利用規約・料金体系の確認が必要 |

ライセンス情報が依存関係ファイルに含まれない場合は、WebSearch または npm・PyPI の公式ページで確認する。
すべてのパッケージのライセンスを確認する必要はない。GPL・AGPL が疑われるパッケージを優先する。
