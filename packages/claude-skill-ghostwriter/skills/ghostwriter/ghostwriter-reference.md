# ghostwriter リファレンス — 執筆ルール詳細

`/ghostwriter` スキル（`SKILL.md`）から参照されるリファレンス。スキル本体ではないため直接呼び出しはできない。
執筆・校正の作業前に、該当セクションを Read してから作業すること。

## Step 3: 表記ルール（漢字かな・数字・英語固有名詞）

### 漢字・かな

| かなで書く | 漢字で書く |
|---|---|
| **助詞**: こと、もの、とき、ところ、ため | 指し示す対象物が具体的な場合（「本社が建っている所」）|
| **補助動詞・補助形容詞**: 〜してみる、〜しておく、〜してある、〜してほしい、〜していい | 本動詞・本形容詞（「街へ行く」「賞状を頂く」）|
| **接続詞**: また、および、しかし、ただし、なぜなら など | — |
| **指示代名詞**: これ、それ、あの | — |
| **形式名詞**: こと（「聞いたことがある」）、もの（「食べるものがない」）、とき（「行ったとき」）| 実質名詞（「大通り」「故あって」）|

**よく誤りやすい語（左 → 右に統一）**

```
出来る → できる    有る  → ある
行なう → 行う      又   → また
及び  → および    但し → ただし
因って → よって    尚   → なお
```

### 数字

- 横書きは**算用数字**を使用
- 4 桁以上は 3 桁ごとにカンマ（例: 1,000,000）
- 単位: 十・百・千は数字のみ、**万・億・兆は漢字**（例: 1 億 2,345 万円）
- 概数・ことわざ: 漢数字（例: 二の舞、三人組）
- 助数詞: 「か所」「か月」（「箇所」「カ所」「ヵ所」は使わない）
- 範囲: 「〜から〜まで」（含む）、「〜より〜未満」（含まない）

### 英語・固有名詞

- 固有名詞は**公式情報の通りに正確に**表記
  - ○ PowerPoint　✗ Powerpoint
  - ○ Microsoft 365　✗ Microsoft365
- 複合語は辞書通りの表記

## Step 4: 文の構造・係り受けルール

### 指示語（こそあど言葉）

原則「**そ**（それ、そこ、その）」を使用。以下の場合のみ「こ」を使用:
- 「この文書自体」を指す場合
- 伝えたいテーマと強く結び付ける場合
- 前述の内容をまとめて結論を示す場合（「このような理由から」）
- あとから出てくるものを先に指す場合

### 接続詞

文脈から関係性が読み取れる場合でも、曖昧さを防ぐために接続詞を明記する。
種類と用途は後述の「接続詞リファレンス」を参照。

### ぎなた読みの防止

語句・文節の区切りを誤って解釈されないよう、以下の対策を取る:
- 漢字かな交じり表記で同音異義語を明確化
- 読点（、）で区切る

```
NG: 「ここではきものをぬいでください。」
OK: 「ここでは、履物を脱いでください。」
```

### 修飾語・被修飾語

- **修飾語と被修飾語はなるべく近づける**（語順を入れ替える）
- 適用範囲が広い修飾語は特に注意

```
NG: 「美味しいお店のケーキと紅茶」（「美味しい」が何にかかるか不明）
OK: 「お店の紅茶と美味しいケーキ」
```

### 否定表現

以下を避ける:
- 部分否定: 「〜はほとんどない」→「〜が少ない」と書く
- 二重否定: 「少なくない」→「多い」と書く
- 否定疑問文

### 助詞の選択

| 助詞 | 主な用法 | 注意 |
|---|---|---|
| から | 起点、理由 | 「起点」の意図なら「から」を使う |
| より | 比較対象、起点 | 起点には「から」を優先し、比較には「より」を使う |

**「の」「に」「も」「て」などの連続使用を避ける**: 連続すると稚拙な印象になるため、別の表現に書き換える。

## Step 5: 文章構成ルール

### タイトル

「〜について」は避ける。**主題 ＋ 文書の性格**で具体的につける。

```
NG: 「インフラ障害について」
OK: 「インフラ障害（2024-06-25）発生報告と再発防止策」

NG: 「新システム導入について」
OK: 「新システム導入提案 — コスト削減効果と移行計画」
```

### 伝えたい内容を目立たせる

1. **伝えたいことを絞る**（1 文章 = 1 主張）
2. **伝えたいことを先頭にする**（結論ファースト）
3. **論点と補足情報を分離する**（補足は脚注・小フォント）
4. **関係ないことは削除する**

#### 記書きの活用

通知書・依頼書・案内状・送付状では「記」「以上」形式を使う。

```
（挨拶文・説明文）

記

・ 〇〇〇〇
・ 〇〇〇〇

以上
```

- 説明文と合わせて 1 ページに収まらない場合は「別記」「別紙」にする
- 詫び状・障害報告書では記書きを使わない
- 横書きの参照: 「下記の」、縦書き: 「左記の」
- 箇条書きを参照させる場合: 「次の」「以下の」

### 主張と根拠

- **最初に結論と根拠**を書く（PREP 法・ピラミッドストラクチャー）
- 根拠は**定量的**（数字・事実・実体験）
- 事実と意見（私見・推定）を分けて書く。意見・推定には根拠を添える
- 受け身表現を避ける（主体性を示す文書で）

### 構造化

文の性質で分類し、同性質でグループ化する:
1. 概要と詳細に分けて、**抽象→具体の順**で説明
2. 結論と理由を先頭に
3. 細かすぎる内容は別紙へ

### 平易な表現

- 難しい言葉・専門用語・カタカナ語は平易な言い回しに置き換える
- 用語定義を冒頭に置く（文書種別によって）
- 脚注・カッコで補足（地の文に修飾語を追加しない）
- 抽象的な説明には「例えば〜」を添える

### 正確さ

- **省略しない**（書き手と読み手が共通認識を持つ場合を除く）
- **主語を書く**（責任の所在を明確にする文書）
- **定性的表現を避ける**（「とても」「かなり」「非常に」→数値で示す）
- 議事録・交渉録: 「決定事項」「宿題事項」「決着時期」「アクションプラン」を明記

### 直感的に理解できる

- 助詞・修飾語を削って主語述語を明確に
- キーワード同士の関係は記号で（＝ → ⇒ ↔）
- 補足説明は脚注へ
- 受動態 → 能動態に書き換える
- タイトル・箇条書きは体言止め（本文には使わない）
- 文章で伝えるより図表が有効な場合は図表を使う

### 図表の作成ルール

設計書・報告書・提案書の表と図に共通して適用する。グラフ種別の使い分けは「Step 6: グラフの使い分け」を参照。

**図表全般**

- 図表には通し番号とタイトルを付ける。**表のタイトルは表の上、図のタイトルは図の下**に置く。本文からは「表 3 のとおり」と番号で参照し、「下の表」のような位置で参照しない
- タイトルは内容を具体的に表す（固有名詞・対象・期間を入れる）。タイトルと中身を一致させる
- **本文と図表で、数値・単位・用語を一致させる**（不一致は読み手の信頼を最も損なう）。本文と図表で同じ内容を二重に書かない
- 図表は本文で必ず言及してから置く。引用した図表には出典を添える
- 同じ種類の図表は、罫線・フォント・列の並びの形式をそろえる

**表**

- **空欄を作らない**。埋められない欄には理由を書く（例: `未定（○月○日決定予定）`、該当なしは `—` とし、凡例か脚注で意味を示す）
- 文字は左揃え、数字は右揃え。小数点以下の桁数を列内でそろえる
- 単位を省かない（列見出しに `（件）`・`（%）` のように書く）
- 3 桁ごとにカンマを付ける。ただし西暦には付けない（`2,024年` としない）
- 罫線は少なくする。縦線は原則として引かず、見出しの区切りなど必要な横線だけにする

**図・グラフ**

- 色だけで系列を区別しない。白黒印刷でも読めるよう、線種・マーカー・濃淡でも区別する
- 円グラフの項目は多くても 10 個以内にし、12 時の位置から時計回りに大きい順に並べる（アンケートの選択肢順など、内容上の順序を優先する場合を除く）
- 横棒グラフは、大きさ順・五十音順・時系列など並べ方の基準を 1 つ決める
- 予測値・推定値は実績値と見分けられるようにする（色を薄くする・破線にする）
- 意味のない色付け・グラデーション・3D 効果を使わない

> 参考文献: 荒瀬康司「科学論文での図表作成のルール」『人間ドック』38 巻 5 号, pp. 659-676, 2024. https://doi.org/10.11320/ningendock.38.659 （© 日本人間ドック学会。ルールの考え方を業務文書向けに要約して書き下ろした。原文は転載していない）

## Step 6: プレゼンテーション資料 固有ルール

### 大原則

| 原則 | 内容 |
|---|---|
| 結論から始める | 読み手が飽きる前に結論を伝える。まとめスライドで再度結論を示す（「ご清聴ありがとうございました」で終わらせない）|
| 全体の流れを示す | 目次でストーリーと終わり時刻を示す。直接関係ない補足は巻末付録へ |
| 1 スライド 1 トピック | 情報を詰め込まない。余白でメリハリをつける |
| メッセージを明確に | タイトル・サマリーで主張と根拠を示し、繰り返す（言い回しを変えない）|
| 認知負荷を下げる | カタカナ語・専門用語を避ける。数字・概念はグラフ・図表で示す |

### 構成フレームワーク

| フレームワーク | 向いている用途 | 構造 |
|---|---|---|
| **PREP 法** | 主観的主張・提案 | Point（結論）→ Reason（理由）→ Example（具体例）→ Point（再結論）|
| **SDS 法** | 客観的事実の報告 | Summary（概要）→ Detail（詳細）→ Summary（再概要）|
| **DESC 法** | 相手への依頼・交渉 | Describe（現状描写）→ Explain（自分の意見）→ Specify（提案）→ Consequence（結果・選択）|

### 提案書のストーリー構成

AsIs（現状課題）→ **解決策** → ToBe（目指す姿）の 3 段構成が基本。解決策は組織・業務フローに合わせた具体的な内容を書く。

### レイアウトの原則

- **整列**: 目測でなく配置機能（PowerPoint の「オブジェクトの配置」等）を使う
- **近接**: 関連するオブジェクトを近づけ、関連しないものを遠ざける
- **反復**: フォント・サイズ・色・余白のルールを最後まで守る。あえて外すのは強調のため
- **視線の流れ**: 左から右、上から下

### グラフの使い分け

| グラフ種別 | 用途 | 注意事項 |
|---|---|---|
| 棒グラフ | 量の大小を比較 | 縦軸は必ず 0 を基準。棒の幅を揃える。プレゼンでは縦軸・目盛線を省略してラベル表示 |
| 折れ線グラフ | 量の増減を比較（時系列）| 縦軸は 0 でなくてよい。横軸は時系列・等間隔。マーカーを設定 |
| 円グラフ | 100% のうちの構成比 | ドーナツグラフ・3D 円グラフは使わない |
| 帯グラフ | 構成比を複数比較 | — |

グラフ作図サンプル（都道府県人口・気温推移・売上高）は同ディレクトリの `グラフ作図サンプル.html` で確認できる。

### 箇条書きのルール

- 短すぎず（単語のみ列挙しない）、長すぎない
- **修飾語 1〜2 個を含む名詞句**が理想
- 詳細は入れ子のリストにする（項目と説明はフォントサイズ・色を分ける）
- 名詞句（体言止め）は句点「。」をつけない

### 前提条件・制約条件の記載

提案書・契約関連資料では必ず以下を明記する:
- 契約範囲（開発対象・対象外）
- 仕様変更時の対応方針
- 利用ライセンス・端末条件
- クラウドサービスの SLA・機能制約
- 障害時・天変地異時の責任範囲
- 稼働時間・作業場所
- 成果物の粒度・検収条件・請求タイミング
- 著作権・著作人格権

## 接続詞リファレンス

文脈に応じて以下から選択する。

| 種類 | 代表的な接続詞 |
|---|---|
| 順接（理由→結論） | だから、そのため、したがって、よって、ゆえに |
| 順接（原因→結果） | すると、その結果、それにより |
| 逆接 | しかし、しかしながら、ところが、にもかかわらず、一方 |
| 並列・列挙 | また、および、第 1 に・第 2 に、まず・次に・そして |
| 添加・累加 | さらに、加えて、そのうえ、しかも |
| 対比 | 一方、逆に、反面、むしろ、それに引き換え |
| 選択 | または、もしくは、あるいは |
| 説明 | なぜならば、というのは |
| 補足 | なお、ただし、ちなみに |
| 言換え | つまり、すなわち、要するに |
| 例示 | 例えば、具体的には、特に |
| 転換 | さて、ところで |
| 条件 | それなら、では、もし〜なら、そうすれば |
