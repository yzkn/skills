# 図の型カタログ（visual-doc 補助ファイル・常時ロードしない）

`/visual-doc` の Step 2 で Read する。モードに対応する節だけ読めばよい。SVG の記法そのものは [`svg_library.md`](svg_library.md) を参照。

> 出典: mhattingpete/claude-skills-marketplace の `visual-documentation-plugin`（Apache-2.0）の `design_patterns.md`・各 `*_components.html` を統合・日本語化したもの。**原典のブランド配色（紫グラデーション）とタイポ体系は採用していない**（下記「AI slop を避ける」）。

---

## 1. 意味色トークン

色は**意味を持つときだけ**使う。装飾目的で色を増やさない。`assets/base_template.html` は以下を CSS 変数（`--c-ok` 等）として定義済みで、ダーク時は自動で明度が切り替わる。

| 役割 | 線・文字 `--c-*` | 塗り面 `--c-*-fill` | 用途 |
|---|---|---|---|
| 成功・完了・肯定 | `#22543d` | `#2f855a` | 完了タスク、正常系、上昇指標 |
| 警告・進行中・要注意 | `#92400e` | `#b45309` | 進行中、判断ノード、遅延予兆 |
| 情報・標準・中立 | `#2a4365` | `#2b6cb0` | 標準の処理・データ・基準系列 |
| エラー・重大・否定 | `#9b2c2c` | `#c53030` | 失敗、異常系、下降指標、マイルストーン線 |
| 処理・変換 | `#9c4221` | `#c05621` | 加工・変換・バッチ処理 |
| 強調・特殊 | `#553c9a` | `#6b46c1` | 外部システム、特別扱いの要素（**多用しない**） |
| 未定・対象外 | `--c-muted` | （塗らない） | 未着手、参考情報、「要確認」 |

- **塗り面（`--c-*-fill`）の上に載せる文字は必ず白**にする（`class="on-fill"`）。SVG の `text` は既定で `--text` になり、**ダークテーマでコントラストが不足する**（実測 4.16:1）
- **塗り面の色はライト/ダーク共通**にしてある。白文字との比 4.5:1 を満たす濃色に統一しているため、テーマごとに変える必要がない
- 淡色面（`--c-*-soft`）の上は本文色（`--text`）。淡色面に白文字を置かない
- 線（stroke）は `--c-*`（塗りより暗い）を使うと境界が締まる。ライト/ダークで反転する
- 【重要】**原典（visual-documentation-plugin）の「白文字は全ての意味色で AA を満たす」という記述は誤り**。原典の明るい塗り色（`#48bb78`・`#4299e1`・`#f59e0b`・`#f56565`・`#ed8936`）は白文字に対して実測 **2.15〜3.05:1** しかなく AA（4.5:1）に不足する。上表の濃色を使うこと。検証は `scripts/verify_output.py` が自動で行う
- **色覚多様性への配慮**: 赤と緑を「唯一の差」にしない。形（角丸/矩形/菱形）・記号（✓ / ! / ×）・テキストラベルを必ず併記する

## 2. AI slop を避ける（本リポジトリ固有）

`/anti-slop-review` が 🔴 Critical として検出する兆候。**生成前に避ける**。

- **紫グラデのヒーロー**（`linear-gradient(135deg,#667eea,#764ba2)` 系）を背景・見出し・カードに敷かない → 単色サーフェス＋左アクセント罫で階層を作る
- **グラデ見出し**（`background-clip: text`）を使わない → 単色。強調はウェイトと余白で
- **アイコン上・見出し・3 行本文の等幅 3 カラム**を並べない → 内容量に応じて列幅・カード高を変える
- **意味のない装飾**（浮遊する円・メッシュ blob・根拠のないバッジ）を置かない
- **捏造メトリクス**（「99.9% 稼働」等の根拠のない数値）を書かない → 不明は「要確認」

## 3. アーキテクチャ図（`architecture`）

構成する節は次の 6 つ。**すべてを毎回作らない**。入力に根拠がある節だけ作る。

1. **ビジネス文脈**: 目的・利用者・提供価値・成功指標（表または定義リスト）
2. **データフロー**: 入力源 → 処理 → 出力を左→右に並べた SVG
3. **処理パイプライン**: 多段処理を上→下または左→右に並べ、各段に入出力を注記
4. **システム構成（レイヤ図）**: データ層 / 処理層 / サービス層 / 提示層を横帯で積む
5. **機能一覧**: 機能要件と非機能要件を分けた表（非機能は測定可能な形で書く）
6. **配置・運用**: 配置モデル・前提条件・運用フロー

### レイヤ図の型

```
┌──────────────────────────────┐  提示層（--c-info）
├──────────────────────────────┤  サービス層（--c-proc）
├──────────────────────────────┤  処理層（--c-warn）
└──────────────────────────────┘  データ層（--c-muted）
```

- 1 レイヤ = 横帯（`rect` 高さ 70〜90px）。帯の中に構成要素を等間隔の小矩形で並べる
- **層をまたぐ依存は矢印で明示**し、下位層から上位層への矢印が出ていないか（依存方向の逆転）を確認する
- 外部システムは点線枠（`stroke-dasharray="6 4"`）＋ `--c-accent` で内外を区別する

### データフロー図の型

左（入力・`--c-info`）→ 中央（処理・`--c-proc`）→ 右（出力・`--c-ok`）。要素は `viewBox="0 0 800 400"` 内で幅 120 / 高さ 80 の矩形、間隔 170px を基準にする。矢印には**流れるデータの名前**を必ずラベルとして添える（無名の矢印は情報量が無い）。

## 4. フローチャート（`flowchart`）

### ノード形状の対応（JIS X 0121 準拠）

| 形状 | 意味 | 実装 | 色 |
|---|---|---|---|
| 角丸矩形 | 開始・終了 | `<rect rx="25">` | 開始 `--c-ok` / 終了 `--c-err` |
| 矩形 | 処理 | `<rect>` | `--c-info` |
| 菱形 | 判断 | `<path>`（`svg_library.md`「菱形」） | `--c-warn` |
| 平行四辺形 | 入出力・データ | `<path>` | `--c-muted` |
| 六角形 | 準備・ループ端 | `<path>` | `--c-proc` |
| 円（小） | 結合子・別ページ接続 | `<circle r="12">` | `--c-muted` |

### レイアウト規則

- **主流（正常系）を一直線に**置く。縦組みなら上→下、横組みなら左→右
- ノード間隔は 100px を基準（矢印の可読性の下限）。ノード高 50〜60px、幅 120〜160px
- 判断ノードの分岐には必ず条件ラベル（`Yes` / `No`、または条件式）を矢印の傍に置く
- 例外系・エラー系は主流の**右側（または下側）へ逃がす**。主流と交差させない
- **スイムレーン**: 担当者・システムごとに横帯（または縦列）を作り、帯の左端にレーン名を置く。帯の境界は `--c-muted` の細線。レーンをまたぐ矢印が「引き継ぎ」を表す
- ループは戻り矢印を主流の外側に回し、直角パス（`M x,y H x2 V y2 H x3`）で描く

### 業務フロー図として使う場合

`requirements-analyst` が作る業務フロー（`design/02_requirements/`）の補助図にする。**現行業務（As-Is）と新業務（To-Be）は別ファイル**にし、ファイル名に `as-is` / `to-be` を含める。差分の強調には `--c-warn` の枠線を使う。

## 5. タイムライン・ガント（`timeline`）

### 構成

1. ヘッダー: 対象名・期間（開始〜終了）・全体進捗（%）・基準日
2. フェーズ帯: 四半期または工程（企画/要件/設計/実装/テスト/移行）で区切る
3. 項目行: タスク名・期間バー・開始/終了日・進捗・ステータス
4. マイルストーン: 到達日と成果物名（`--c-err` の縦線＋ラベル）

### 期間バーの型

- 1 行 = 1 タスク。バーの**左端 = 開始日、幅 = 期間**。行の高さ 28〜32px、行間 8px
- バーの塗りはステータスで決める: 完了 `--c-ok` / 進行中 `--c-info` / 未着手 `--c-muted` / 遅延 `--c-err`
- 進捗は**バー内の内側バー**（同色の暗い版）で表す。数値も併記する（色だけに頼らない）
- **基準日（今日）の縦線**を `--c-err` の点線で引き、ラベルを上端に置く。遅延判定（終了予定日 < 基準日 かつ 未完了）は行に `⚠ 遅延` バッジを付ける
- 日付軸は上端に固定表示し、月または週の目盛を `--c-muted` の縦グリッドで薄く引く

### `task/` を入力にする場合

WBS（`task/wbs.md` 等）から生成する派生物として扱う。**WBS を編集してはならない**（`.claude/rules/wbs-tasks.md` は本スキルの対象外＝読み取りのみ）。WBS ID を行に表示し、正本との対応を追えるようにする。

## 6. データ可視化（`dashboard`）

**プロジェクト状況の可視化は `/project-dashboard` を使う。** このモードは任意データ（計測値・集計結果・分析結果）を可視化する場合に使う。

### KPI カード

- 構成: ラベル（小さく `--c-muted`）／値（大きく太字）／変化（記号＋数値＋期間）
- 変化の記号は `↑`／`↓`／`→` を**必ず数値と併記**する。上昇が良いとは限らないため、色は「良い/悪い」ではなく指標の意味に従って決める（例: エラー率の上昇は `--c-err`）
- カード面は単色。**グラデーションを敷かない**。境界は 1px の罫線＋控えめな影に留める
- 比較対象（前期・目標）を必ず添える。単独の数値は解釈できない

### チャートの選び方

| 目的 | 図 | 注意 |
|---|---|---|
| 項目間の量の比較 | 縦棒（項目 ≤ 8）／横棒（項目 > 8・ラベルが長い） | 軸は 0 起点。途中から始めない |
| 時系列の推移 | 折れ線（系列 ≤ 4） | データ点をマーカーで示す。欠測は線を切る |
| 構成比 | 横積み棒（推奨）／円・ドーナツ（区分 ≤ 4） | 円は面積比較が難しい。値をラベルで併記 |
| 単一値の達成度 | 進捗バー／ゲージ | 目標値と現在値の両方を表示 |
| 状態の一覧 | 信号色ステータス＋記号 | 色＋記号＋テキストの 3 重表現 |

- **凡例よりも直接ラベル**を優先する（系列名を線・バーの傍に置く）
- 目盛の桁は揃え、単位を軸ラベルに明記する（`千円`・`件/日` 等）
- 5 個以上のチャートを 1 画面に並べる場合、**最も重要な 1 枚を大きく**して視線の起点を作る（等幅の格子に並べない）

計算式（ドーナツの `stroke-dasharray`・ゲージの角度・軸のスケール変換）は `svg_library.md`「チャート部品」を参照。

## 7. 技術ドキュメント（`techdoc`）

### 構成

1. 概要（目的・対象読者・技術スタック）
2. 前提と導入手順
3. リファレンス（API エンドポイント／設定項目／CLI）
4. コード例
5. 構成図（`architecture` の型を流用）
6. 手順・ワークフロー

### API エンドポイントブロックの型

- 1 エンドポイント = 1 カード。左端に 4px のアクセント罫（メソッド色）
- メソッド色: `GET` `--c-ok` / `POST` `--c-info` / `PUT`・`PATCH` `--c-warn` / `DELETE` `--c-err`。**メソッド名は必ずテキストで書く**（色だけで区別しない）
- 各カードに「要求」と「応答」を対で示す。応答は**成功例と代表的なエラー例の両方**を載せる
- パスパラメータは `{id}` 形式で統一し、直後に型・必須・説明の表を置く
- エラー応答の形式は `.claude/rules/api-conventions.md`（`/api-guide`）に従う。**このファイルで独自形式を発明しない**

### コードブロック

- 等幅フォント・横スクロール可（`overflow-x: auto`）。**行折り返しはしない**
- 構文ハイライトは外部 JS を使わないため、**色付けは行わない**（自己完結要件を満たすため）。強調が必要な行は左に `--c-warn` の細罫を付ける
- コード内に**実在の認証情報・実データを書かない**（`YOUR_API_KEY`・`example.com`・架空の ID を使う）

## 8. アクセシビリティのチェック項目

- 本文コントラスト 4.5:1 以上、18pt 以上または 14pt 太字は 3:1 以上
- 色以外の手がかり（形・記号・ラベル）が必ずある
- SVG に `<title>` を入れる。装飾のみの SVG は `aria-hidden="true"`
- 図の直後に**要点を 1〜2 文のテキスト**で書く（図を読めない環境・スクリーンリーダー向け。同時に「図が何を主張しているか」の明示にもなる）
- 表には `<caption>` と `<th scope>` を付ける
