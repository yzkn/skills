# /visual-doc スキル — 自己完結 HTML 図表の生成

**引数:** `$ARGUMENTS`（`<モード> [対象・出力名]`。モード省略時は依頼内容から推定して宣言する）

外部ライブラリ・CDN に依存しない**インライン SVG の図**を、単一 HTML ファイルとして生成する。`design/` の設計書に添える補助図、`report/` の可視化のいずれにも使う。

> 出典: [mhattingpete/claude-skills-marketplace](https://github.com/mhattingpete/claude-skills-marketplace) の `visual-documentation-plugin`（Apache License 2.0、`LICENSE` 参照）。原典の 5 スキルを 1 スキルに統合し、リファレンスの 4 重複を解消、配色・タイポ体系は本リポジトリの規約（`anti-slop-review` / `ui-ux-pro-max`）に差し替えたうえで日本語化した。

## モードと出力先

| モード | 用途 | 出力先 |
|---|---|---|
| `architecture` | システム構成・レイヤ図・データフロー・処理パイプライン | `design/03_basic_design/diagrams/<名前>.html` |
| `flowchart` | 業務フロー・処理フロー・判断ツリー・スイムレーン | `design/02_requirements/diagrams/`（業務）または `design/03_basic_design/diagrams/`（処理） |
| `timeline` | タイムライン・ロードマップ・ガントチャート | `report/dashboard/timeline_<名前>.html` |
| `dashboard` | 任意データの KPI カード・チャート・進捗 | `report/dashboard/<名前>.html` |
| `techdoc` | API リファレンス・技術解説（コード例付き） | `design/04_detailed_design/<名前>.html` |

出力先ディレクトリが存在しない場合は作成する。ファイル名はユーザー指定を優先し、無指定なら対象名の英小文字ケバブケースにする。

**このテンプレートリポジトリ自体（`.claude/` の改修・スキルの検証等）を対象にする場合は、上表ではなく `wip/` に出力する**（`design/`・`report/` は展開後の案件成果物の置き場。ルート `CLAUDE.md`「成果物・証跡の格納先」）。

## 既存スキルへの委譲（先に確認する）

**この 3 つに当てはまる依頼は、本スキルではなく既存の手段を使う**。図の生成が必要な部分だけ本スキルに戻ってくる。

| 依頼 | 委譲先 |
|---|---|
| `task/`・`design/`・`doc/adr/`・`report/` を集約したプロジェクト状況の可視化 | `/project-dashboard`（データ収集ロジックを持つ） |
| 実装済みコードからの API 仕様書（OpenAPI 3.0） | `api-spec-generator` サブエージェント。`techdoc` は人間向け解説を作る場合のみ |
| Markdown / Word / PowerPoint として配布する文書 | `/ghostwriter`・`/office-pandoc`・`/slides-maker` |

## 生成の必須要件

- **自己完結**: 外部 CDN・Web フォント・外部画像・外部 JS を参照しない。CSS/JS はインライン、図はインライン SVG（グラフ描画ライブラリを使わない）
  - **サービス・製品のアイコンを入れる場合は、ライセンスを確認したうえで必ず data URI で埋め込む**（`<img src="data:image/png;base64,...">`。`.claude/rules/third-party-licenses.md`）。**URL 参照のまま貼らない**（この自己完結要件に反する）。表示サイズの 2 倍のサイズ変種を選ぶ（PNG のため拡大に弱い）
- **ライト/ダーク両対応**: `prefers-color-scheme` に対応する（`assets/base_template.html` が対応済み）
- **日本語 UI**・レスポンシブ（モバイル幅でも横スクロールが発生しないこと。横長の表・図は個別に `overflow-x: auto` の親要素へ入れる）
- **アクセシビリティ**: 本文コントラスト 4.5:1 以上。**色だけで情報を伝えない**（形・ラベル・記号を併記）。SVG には `<title>` を入れる
- 【絶対禁止】**データの捏造**。数値・日付・ステータスが不明な箇所は「要確認」と表示する。それらしい値で埋めてはならない
- **AI slop 回避**: 紫グラデのヒーロー（`#667eea`→`#764ba2` 系）・グラデ見出し・意味のない装飾グラデ・アイコン付き 3 等分カードグリッドを使わない。詳細は `references/diagram_patterns.md`「AI slop を避ける」と `/anti-slop-review`

### `design/` に出力する場合の追加規約

設計書は **Markdown が正本**（`.claude/rules/design-docs.md`）。HTML の図は**派生物**として扱う。

- 対応する Markdown 正本（同フェーズの設計書）に、図が示す内容（構成要素・関係・前提）を文章または表で記述する。**HTML だけが情報源になる状態にしない**
- HTML 冒頭に「本ファイルは `<正本のパス>` の補助図。正本の更新時に再生成する」旨を明記する（テンプレートの注記欄を使う）
- 未確定情報は正本と同じく `==〜==` の意図を保ち、HTML 側では「要確認」バッジで表す

## 実行手順

### Step 1: 入力の確定

依頼内容・対象ファイル（`design/`・`task/`・`intake/extract/`・ソースコード等）から、図に描く要素を洗い出す。**不足している情報は推測で埋めず、この時点でユーザーに確認する**（要素名・関係・期間・数値）。

### Step 2: 図の型を選ぶ

`references/diagram_patterns.md` を Read し、モードに対応する節から図の型と意味色を選ぶ。要素数が多い場合は 1 枚に詰め込まず、図を分割する。

### Step 3: SVG を実装する

SVG の記法（矢印マーカー・菱形・ベジエ・ドーナツの計算・軸）が必要になった時点で `references/svg_library.md` を Read する。座標は先に紙上で決めてから書く（`svg_library.md`「座標計算の手順」）。

### Step 4: HTML を組み立てる

`assets/base_template.html` を土台にする（CSS 変数・ダーク対応・注記欄・カード・表・バッジ・SVG 既定スタイルを含む）。プレースホルダ（`{{...}}`）を実データで置換し、不要な節は削除する。

### Step 5: 検証（スクリプトで機械的に行う）

```
python .claude/skills/visual-doc/scripts/verify_output.py <生成したファイルのパス>
```

自己完結性・AI slop 兆候・**WCAG コントラスト比（ライト/ダーク両テーマ）**・`viewBox` のはみ出し・`<title>` の有無・テキスト幅の概算を検証し、不合格があれば終了コード 1 で一覧を出す。**合格するまで修正する**。目視のセルフチェックでは落ちる項目があるため省略しない（このスクリプトは初回の検証で、原典由来の明るい塗り色が白文字に対して 2.15〜3.05:1 しか出ないことを検出している）。

スクリプトで検出できない以下は読解で確認し、報告に含める。

1. 「要確認」以外の数値・日付・ステータスがすべて入力に根拠を持つこと
2. 図の主張と `figcaption` の説明文が一致していること
3. 矢印が意図した要素同士を繋いでいること（座標のずれ・重なり）
4. モバイル幅（375px）で横スクロールしないこと（横長の表・図が `.scroll-x` の内側にあるか）

### Step 6: 報告

生成先パスと、図から読み取れる要点（または入力の不足点）を 3 点以内でチャットに要約する。`--artifact` 指定時、または共有を依頼された場合のみ Artifact として公開する（顧客名等の機微情報を含む場合は公開前にユーザーへ確認する）。

## 完了条件

- [ ] 単一 HTML として生成され、外部リソース参照が 0 件
- [ ] ライト/ダーク両方で本文が読めるコントラストになっている
- [ ] 色以外の手がかり（ラベル・形・記号）で情報が判別できる
- [ ] 入力に根拠のない数値・日付が含まれていない（不明は「要確認」）
- [ ] `design/` 配下に出力した場合、対応する Markdown 正本に同じ情報が記述されている
- [ ] セルフチェック 4 項目の結果を報告した
