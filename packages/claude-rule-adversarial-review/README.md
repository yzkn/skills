## これは何か

成果物を「正しいと示す」のではなく「誤りを見つける」方向で 1 パス検証する規律。実施タイミング 6 種、自己内省パスと独立パス（サブエージェント 1 体）の使い分け

## なぜ作られたか

「完了の証拠主義」が**検証したか**を問うのに対し、**反証を試みたか**を問う規律が未整備だった。ADR-016 で望ましいとした「観点を分けた独立検証」を発動タイミング付きで明文化（コミット `7a5b375`、2026-07-31）。3 体以上の並列起動を【要指示】としたのは、ensemble-solving を見送った判断（ADR-016）と整合させるため

## 導入

```sh
mkdir -p .claude/rules
cp rules/adversarial-review.md .claude/rules/
```

常時適用したい場合は `CLAUDE.md` に `@.claude/rules/adversarial-review.md` の行を追加する。frontmatter に `paths:` があるルールは `@` 行に**加えない**（加えると常時ロードになり、条件付きの意味が失われる）。
