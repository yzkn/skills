# /handoff スキル — 会話を次のセッションへ引き継ぐ

**引数:** `$ARGUMENTS`（`[次のセッションで何をするか]`。指定された場合はその目的に合わせて内容を絞る）

いまの会話を要約し、**文脈を持たないエージェント（または別の担当者）が続きを始められる**引き継ぎ文書を書く。

> 出典: [mattpocock/skills](https://github.com/mattpocock/skills)（MIT License、`LICENSE` 参照。Copyright (c) 2026 Matt Pocock）の `productivity/handoff`。出力先・機密の扱い・隣接スキルとの切り分けを本リポジトリの運用に合わせて追加した。

---

## 使い分け

| 目的 | 使うもの |
|---|---|
| 次のセッション・別担当が**作業を続けられる**ようにする | 本スキル（一時的な作業文書） |
| 会話を**証跡として残す**（あとから書き換えない） | `/record`（`doc/prompt/`・`doc/thought/`） |
| 覆しにくい判断の経緯を残す | `/record adr`（`doc/adr/`） |
| セッションリミットで中断した作業を自動で再開する | `/auto-resume`（中断前の指示を次回セッションへ注入する） |
| コンテキストの詰まりを解消する | `/context-engineering` |

`/record` との違いは**書き換えの可否**である。証跡は不変で、引き継ぎ文書は作業が進めば古くなる。**引き継ぎ文書を `doc/prompt/`・`doc/thought/`・`doc/adr/` に置いてはならない**（`.claude/CLAUDE.md`「証跡の不変性」）。

---

## 出力先

- 既定は **OS の一時ディレクトリ**（このセッションのスクラッチパッド）。作業リポジトリを引き継ぎ文書で汚さない
- 案件の記録として残す必要がある場合のみ `report/handoff/{yyyymmdd}-{ケバブケースの主題}.md`
- どちらに置いたかを**パスとともに報告する**（次のセッションはこのパスを読むところから始まる）

---

## 書く内容

1. **いま何をしていたか** — 目的と、この会話で確定したこと
2. **どこまで進んだか** — 完了した作業と、その裏付け（実行したコマンドと終了コード・変更したファイル）
3. **次にやること** — 具体的な次の一手。判断待ちの事項があれば、誰の判断待ちかを明記する
4. **踏んではいけない地雷** — この会話で判明した制約・失敗した方法とその理由（同じ失敗を繰り返させない）
5. **推奨スキル** — 次のエージェントが Skill ツールで呼ぶべきスキル名を挙げる（例: `/design-sync`・`/tdd`）
6. **参照先** — 関連する設計書・ADR・課題・コミット・差分のパスまたは URL

## 書かない内容

- **他の成果物に既にあるものを写さない。** 仕様書・計画・ADR・課題・コミット・差分は**パスか URL で参照する**（重複した写しは、正本が更新された時点で誤情報になる）
- **会話の逐語再現をしない。** 逐語の記録は `/record` の役割である
- 【絶対禁止】**認証情報・個人情報を書かない。** API キー・パスワード・トークン・接続文字列・氏名・メールアドレス・電話番号は伏せる（`.claude/rules/security-hardstops.md`）。`report/handoff/` に置く場合は git 管理下に入るため、コミット前に `.claude/rules/git-safety.md`「コミット前の機密情報チェック」を行う

---

## 完了条件

- 文脈を持たない読み手が、次の一手を自分で始められる
- 完了報告に事実（コマンド・終了コード・変更ファイル）と判断が分けて書かれている（`.claude/rules/code-quality.md`「完了の証拠主義」）
- 他の成果物の内容を写さず、参照で示している
- 認証情報・個人情報が含まれていない
- 出力先のパスを報告に明記した
