## RCA 手法（5 Whys・Fishbone 分析）

**5 Whys 手法**

「なぜ」を 5 段階掘り下げて根本原因を特定する。

```
問題: 注文確定 API が 45 分間 503 を返した

Why 1: なぜ 503 を返したか？
→ アプリサーバーのスレッドプールが枯渇したため

Why 2: なぜスレッドプールが枯渇したか？
→ DB クエリのレスポンスが通常の 50 倍遅くなったため

Why 3: なぜ DB クエリが遅くなったか？
→ 定期バッチが全件スキャンを実行しロックが競合したため

Why 4: なぜ定期バッチが全件スキャンをしたか？
→ バッチの WHERE 句に使用しているカラムにインデックスがなかったため

Why 5: なぜインデックスがなかったか？
→ テーブル設計時にバッチ処理の実行頻度を考慮していなかったため

根本原因: テーブル設計時の考慮漏れによりインデックス未設定のままデプロイされた
```

**Fishbone 分析（必要に応じて）**

原因が複数の要素に分散している場合は、以下のカテゴリで整理する。

| カテゴリ | 確認観点 |
|---|---|
| 人（People） | 判断ミス・スキル不足・コミュニケーションエラー |
| プロセス（Process） | レビュー不足・デプロイ手順の問題・監視設定の漏れ |
| 技術（Technology） | 設計上の欠陥・既知バグ・インフラの問題 |
| 外部（External） | 外部サービス障害・クラウドプロバイダーの問題 |
