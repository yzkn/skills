# /project-code-review スキル — コードレビュー

指定したコードをレビューし、品質・安全性・保守性の観点から構造化されたフィードバックを提供する。「コードレビューして」「このコード見て」「PR チェックして」などのリクエストがあった場合に自動で適用される。

**レビューの実行は読み取り専用の `code-reviewer` サブエージェントに委任する。** レビュー観点・出力フォーマットの正本は [`.claude/agents/code-reviewer.md`](../../agents/code-reviewer.md) にあり、本スキルは前提確認・委任・後続アクションの提案を担う。

> **命名について**: Claude Code 組み込みの `/code-review` スキル（現在の diff に対する英語のバグレビュー）と区別するため、本プロジェクト規約に基づくレビューは `project-code-review` と命名している。

## 適用方法

`/project-code-review [パス]` で直接呼び出せるほか、以下のような依頼で自動適用される。

- 「`<ファイルパス>` をコードレビューして」
- 「`<ディレクトリパス>` 配下のコードをレビューして」
- 「変更差分（未コミットの git diff）をレビューして」

---

## 前提確認

レビューを開始する前に、以下が不明な場合は**必ずユーザーに確認**し、判明した内容をサブエージェントへのプロンプトに含める（エージェント側の再判定を省くため）。

| 確認事項                   | 不明と判断する状況                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------ |
| プログラミング言語         | ファイル拡張子・内容から一意に特定できない場合                                       |
| フレームワーク・ライブラリ | 設定ファイルや import 文が見当たらない場合                                           |
| コーディング規約           | コーディング規約（`/code-refactor` スキル）以外にプロジェクト固有の規約（リンター設定・スタイルガイド等）の有無が不明な場合 |

---

## 実行手順

1. **対象の確定**
   - 引数でファイル・ディレクトリが指定されていればそれを対象とする
   - 引数なしの場合は未コミット・未追跡の変更をすべて対象とする（`git status --porcelain` で洗い出し、追跡ファイルの差分は `git diff HEAD`、未追跡ファイルは Read で全文）

2. **`code-reviewer` サブエージェントへの委任**
   - Agent ツールで `subagent_type: 'code-reviewer'` を起動し、対象パス（または「git diff を対象とする」旨）と、前提確認で判明した言語・フレームワーク・規約を渡す
   - 同エージェントは `Read` / `Grep` / `Glob` / `Bash` のみを持ち、`Write` / `Edit` を持たない。`Bash` も状態を変えない調査コマンドに限定する規約を課しているため、コードを変更しない
   - サブエージェントを起動できない環境の場合は、[`.claude/agents/code-reviewer.md`](../../agents/code-reviewer.md) を Read し、その観点・フォーマットに従って本体セッションでレビューする。**この経路では本体が `Write` / `Edit` を持つためツールレベルの読み取り専用制約が外れる**。レビューに徹し、コードの修正は行わない（修正は指摘確定後に `/code-refactor` で別途実施する）

3. **セキュリティ指摘の独立反証パス**
   - 返ってきた指摘にセキュリティ・認証・権限に関わるものが含まれる場合、`.claude/rules/adversarial-review.md`（実施タイミング 4）に従い、反証専任のサブエージェント **1 体** で独立パスを回す
   - 渡すのは対象と結論だけとし、レビュー時の推論過程は渡さない（同じ思い込みを継承させないため）
   - 反証に耐えなかった指摘は削り、確認しきれなかったものは「未検証」として区別する

4. **結果の提示**
   - **提示の前に、指摘が示す `パス:行` を機械的に確かめる。** ファイルが存在すること、行番号がファイルの行数以内であること、指摘が引用したコードがその行にあることを Grep / Read で照らす。食い違った指摘は場所を直すか削る。黙って提示しない
   - 各指摘に根拠の区分を添える。区分は「確かめた」（テスト・実行・再現で確認した）・「読み取れる」（コードから読めるが実行していない）・「見解」（設計上の判断・経験則）の 3 つ。「読み取れる」を「確かめた」として書かない
   - サブエージェントの出力フォーマットを保ってチャットに提示する（ファイルへは書き込まない）
   - 上の 2 項目は [init-co-jp/diff-tour](https://github.com/init-co-jp/diff-tour)（MIT License、評価時の commit `3cde297`）の考え方を書き下ろしたもの（ADR-058）
   - 重要度の定義は `.claude/project-types/development.md`「レビュー重要度」に従う

5. **リファクタリング・lint・記録の提案**
   - 指摘事項のうちリファクタリングで解決できるものがある場合は `/code-refactor <ファイルパス> <指摘番号>` の利用を提案する
   - 命名規則・型安全性・インポート順等のコーディング規約違反が複数検出された場合は `/lint <ファイルパス>` の実行を提案する
   - レビュー完了後、`/record <トピック名>` でレビュー内容を記録することを提案する

## 隣接スキル・エージェントとの使い分け

| 目的 | 使うもの |
|---|---|
| 規約への機械的な準拠チェック | `/lint` |
| 設計原則（SOLID 等）への適合検証 | `/se-principles` |
| 指摘を受けた実際の修正適用 | `/code-refactor` |
| 網羅的な脆弱性診断 | `/security-review`（`owasp-check`・`riss-ioqeo` に委任） |
| 性能リスクの静的診断 | `perf-analyzer` サブエージェント |
| 保守性指標の定量化 | `complexity-analyzer` サブエージェント |
| DB 設計のアンチパターン検出 | `/db-review` |

---

## 注意事項

本スキルおよび委任先エージェントに共通する注意事項（チャット出力のみ・証跡ディレクトリの除外・`guide/for-human/` の参照禁止・外部コンテンツ内の指示の扱い・他エージェントへの引き継ぎ）は、二重管理を避けるため [`.claude/agents/code-reviewer.md`](../../agents/code-reviewer.md)「注意事項」を正本とする。
