# /citation-format スキル — 引用・典拠の書式規約

外部ソース（受領資料・論文・記事・Web ページ・規格文書）を文書内で引用するときの書式を統一する。

> 出典: [mathbullet/skills](https://github.com/mathbullet/skills)（MIT License、`LICENSE` 参照）の `writing-quotation` と `documenting-with-sources` を 1 スキルに統合し、本リポジトリ向けに適応。**典拠一覧の書式は原典の行形式を採らず、既存 `/research` の信頼性付き表形式に統一した**。`>` blockquote の禁止は適用範囲を `design/`・`report/` に限定した。

## 適用範囲

| パス | 扱い |
|---|---|
| `design/**`・`report/**` | **必須**。[`.claude/rules/citation-format.md`](../../rules/citation-format.md) が自動ロードされる |
| それ以外（チャット応答・`doc/`・`src/` のコメント等） | 任意。従ってもよいが強制しない |

<!-- profile:standard-only 「なぜ原文を併記するか」は文書作法の一般論 -->
## なぜ原文を引用するか

要約だけでは、書き手の読み取りが正しいかを読み手が判定できない。原文を併置することで、読み手は書き手の解釈を原典と突き合わせられる。引用（原典の言葉）と地の文（書き手の要約・解釈）は、視覚的にも構造的にも分離し続ける必要がある。
<!-- /profile:standard-only -->

## 1. 引用ブロックの書式

**引用はコードブロック（フェンス）の中に置く。`>` の blockquote 記法は使わない。** 散文・プロンプトテンプレート・コード・XML タグ付きテキストのいずれであっても同じ扱いとする。

構造は次のとおり。

- 開始フェンス
- 原文
- 空行 1 つ
- 訳文（原典が日本語でない場合のみ）
- 終了フェンス
- **終了フェンスの次の行**に典拠参照 `[label (YYYY/MM), 位置]`

規則:

- 原文と訳文は同じコードブロック内に置き、空行 1 つで区切る
- 原文と訳文の間に水平線（`---`）を入れない
- 訳文をコードブロックの外へ出さない。原文の隣に括弧書きで添えない
- 典拠参照は終了フェンスの次の行に独立した行として置く。**コードブロックの中に入れない**

### 例: 同一言語の引用

````markdown
```
処理対象は前営業日までに確定した受注データとし、当日分は翌日のバッチで処理する。
```

[顧客業務要件メモ (2026/05), 3.2 節]
````

### 例: 訳文を伴う引用

````markdown
```
The system SHALL retain audit logs for a minimum of 90 days.

システムは監査ログを最低 90 日間保持しなければならない。
```

[ACME-SEC-STD (2026/03), Section 4.1]
````

## 2. 文中参照の書式

形式は `[label (YYYY/MM), 位置]`。

| 要素 | 内容 |
|---|---|
| `label` | 情報源の識別子。資料名・媒体名・発行元の略称を使う |
| `(YYYY/MM)` | 年月。日は入れない。年しか分からない場合は `(YYYY)` |
| `位置` | 引用箇所（`p.4`・`3.2 節`・`図 2`・`シート「集計」`・`冒頭`等）。特定できない場合は省略 |

位置を省略する場合は `[label (YYYY/MM)]` とする。

- **`[1]`・`[2]` のような裸の番号参照は使わない**。読み手が本文と典拠一覧を往復しないと何を指すか分からず、可読性が落ちる
- 同一の情報源には同一の `label` を使い続ける

## 3. 典拠一覧の書式

文書末尾の典拠一覧は、`/research` と同じ**信頼性付きの表形式**に統一する（原典の行形式は採用しない）。

```markdown
## 情報源一覧

| 信頼性 | 情報源 | URL / 所在 | 参照箇所 |
|---|---|---|---|
| 🟢 高 | ACME-SEC-STD（発行元: ACME 社情報セキュリティ部） | intake/customer/acme-sec-std.pdf | 4.1 節 |
| 🟡 中 | ベンダー技術ブログ「〇〇の実装」 | https://example.com/blog/xxx | 全体 |
| 🔴 低 | 個人ブログ | https://example.net/post/yyy | ※信頼性低 |
```

- 信頼性の判定基準は [`/research`](../research/SKILL.md) の Phase 3 に従う
- 受領資料など URL を持たない情報源は、リポジトリ内の所在（`intake/...`）を書く
- `- [1] ...` のリスト形式は使わない

## 4. 事実的記述には典拠を付ける

- 文書内の事実的記述には典拠を付ける。典拠に結び付けられない記述は「典拠未確認」と明示する。無典拠のまま紛れ込ませない
- **推測・解釈は原典の記述と区別する**。原典が書いていない関連付け（「これは X に関係する」「Y に応用できる」「Z を示唆する」）を、原典の説明として書かない
- 会話や案件の文脈を、原典の説明の中へ持ち込まない。原典の記述はその原典の内容の範囲に留める

## 5. アンチパターン

| # | やってはいけないこと | 直し方 |
|---|---|---|
| 1 | `>` blockquote で引用する | コードブロックで囲む |
| 2 | 訳文をコードブロックの外に散文として置く | 原文と同じブロック内に空行 1 つで並置する |
| 3 | 訳文を原文の隣に括弧書きで添える | 同上 |
| 4 | 典拠参照をコードブロックの中に書く | 終了フェンスの次の行に独立した行として置く |
| 5 | `[1]` 等の裸番号で参照する | 情報源を直接示す `label` を使う |
| 6 | 原文と訳文の間に `---` を置く | 空行 1 つで区切る |
